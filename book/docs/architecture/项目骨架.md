# 项目骨架与目录结构说明

> 实现现状已由 [2026-10-08 Android 运行快照](2026-10-08-android-runtime.md) 取代；下文保留 stage 01/02 当时的结构与规划，不作为当前能力清单。

> 多会话模拟器（multi-session-device）：面向软件测试人员的 Electron 桌面工具。左侧管理多个完全隔离的模拟器实例（安卓 AVD / iOS Simulator，登录态与应用数据互不影响），右侧以单画面投屏当前实例并直接操控（左侧列表是唯一切换入口）。暂无后端模块，一切能力都在本地三进程内。
>
> 本文档描述仓库的目录结构、`src/` 各子目录职责与规划模块落点。**Stage 01（2026-10-01）已把脚手架改造成规范骨架**：UI 基建（styled-components + zustand + lucide-react）、main/preload 业务目录、shared 契约层、原生对话框通道已落地；**Stage 02（2026-10-03）已落地设计系统**：DESIGN.md（仓库根）、themeSystems token 单源、styled-components 主题注入链与亮暗三态、元素基线五件、vitest 测试基建。未落地模块仍以【规划】标记，落地时更新本文。需求依据见 `book/docs/PRD.md`，工作规则见 `book/guidelines/`，阶段跟踪见 `book/stage/`。结构与命名参考姊妹项目 `multi-session-browser/docs/项目骨架.md`。

## 一、技术栈与三进程结构

- **Electron 39 + electron-vite 5 + TypeScript 5.9**，包管理只用 npm
- **主进程**（`src/main/`）：Node 环境——窗口创建、模拟器实例生命周期（AVD/Simulator 管理、子进程池）、画面流编排、IPC handler
- **预加载桥**（`src/preload/`）：contextBridge，向 renderer 暴露白名单 `window.api`
- **渲染进程**（`src/renderer/`）：React 19 纯 UI，禁止直接访问 Node/Electron API；样式用 styled-components（无组件库、不引 tailwind），状态用 zustand 5，图标 lucide-react（2026-10-01 拍板，见 PRD 第 6 节）
- **契约层**（`src/shared/`）：三进程共用的类型与通道名——跨进程通信单源（stage 01 落地；运行时守卫在 main 侧 handler，随业务补充）

数据流单向：主进程是唯一事实源（实例列表、运行状态、画面流归属均由主进程持有并推送快照），renderer 只是镜像 + 发命令。

| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/main/index.ts`                       | 瘦入口：app 生命周期 + 装配（窗口创建、IPC 注册）                                                                                                  |
| `src/main/window/`                        | 主窗创建：尺寸、preload 挂载、外链拦转系统浏览器                                                                                                   |

| `src/preload/index.ts` + `api/`           | contextBridge 白名单暴露 `window.api`（现仅 `dialog`）；不暴露原始 ipcRenderer                                                                     |
| `src/shared/ipc-channels.ts` + `types.ts` | IPC 通道名单源 + 跨进程类型（DialogOptions / DialogResult）                                                                                        |

| `src/renderer/src/App.tsx`                | 骨架自检壳（stage 02 起 tokens 化）：元素基线演示 + 亮暗三态切换 + 原生对话框验证                                                                  |
| `src/renderer/src/styles/global.css`      | 全局 reset + `:root` 琥珀缺省（对账基准）；color-scheme 与 token 由主题注入链同步切换                                                              |
| `src/renderer/src/theme/`                 | 主题注入链（stage 02）：`applyTheme`（CSS 变量 + color-scheme 同链路）+ `DeviceThemeProvider`（styled-components 主题对象从单源派生）              |
| `src/renderer/src/stores/`                | zustand store（appStore 自检计数；themeStore 主题选择 systemId + mode，localStorage 持久化）                                                       |
| `src/renderer/src/components/`            | 元素基线（Button / Input / ListRow / Divider / SegmentedControl，stage 02）+ 业务组件（stage 03 起填）；测试放同级 `__tests__/`（见 coding-style） |
| `src/renderer/src/hooks/`                 | 全局 hooks（stage 03 起填；书写规范见 `guidelines/coding-style.md`）                                                                               |
| 各目录 `__tests__/`                       | 测试与源码同目录共置：`<模块名>.test.ts(x)`，vitest 通配自动发现，`npm run test` 执行                                                              |

### 规划模块（【规划】= 未落地，落点来自调研报告与 PRD）

| 落点                                                            | 职责                                                                                                                                                                                  |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/main/emulator/sdk.ts`【规划】                              | Android SDK 组件检测与引导安装：cmdline-tools + emulator + system image + platform-tools 四件（不需要 Android Studio），SDK 许可写入 licenses 哈希文件；可复用用户已有 `ANDROID_HOME` |
| `src/main/emulator/avd.ts`【规划】                              | AVD 生命周期：create / delete / duplicate（会话克隆=分区复制）/ erase——对应姊妹项目 `main/sessions.ts` 的编排模式                                                                     |
| `src/main/emulator/runner.ts`【规划】                           | 模拟器子进程池：`emulator -no-window -port <5554-5682> -gpu swiftshader_indirect` 启动、崩溃重启、`-snapshot` 会话快速恢复；端口即实例身份                                            |
| `src/main/scrcpy/stream.ts`【规划】                             | 安卓画面流：Tango ADB 连接池 + scrcpy server 生命周期；流经 IPC/MessagePort 送渲染端                                                                                                  |
| `src/main/simulator/`【规划·iOS】                               | iOS Simulator 实例管理：simctl clone / erase / boot（仅 macOS，依赖 Xcode）；画面采集走 ScreenCaptureKit（需「屏幕录制」授权），触控注入走 idb/CGEvent（需「辅助功能」授权）          |
| `src/shared/sessions.ts`【规划】                                | 跨进程会话契约：实例元数据 + 状态机（创建中 / 启动中 / 运行中 / 停止——冷启动 20-60s 必须异步化）+ 通道名；同构平移姊妹项目同名文件                                                    |
| `src/renderer/src/components/device/DeviceCanvas.tsx`【规划】   | 安卓画面嵌入端：WebCodecs 解码 + canvas 渲染 + 指针事件转 scrcpy 控制消息                                                                                                             |
| `src/renderer/src/components/`（会话栏 / 设备画布编排）【规划】 | 左右分栏编排：左侧列表是唯一切换入口（PRD 已推翻 tab 条），切换即画面流的启停与挂起                                                                                                   |

## 四、关键横切约定（写代码前先知道）

1. **实例隔离是生命线**：每会话一个独立 AVD（克隆产生，数据目录互不影响）或独立 Simulator 设备；禁止共享分区/设备——这是产品的一等公民语义。
2. **IPC 白名单纪律**（承自姊妹项目）：renderer 一切经 `window.api` 白名单；通道名单源 `src/shared/`；主进程 handler 先过运行时守卫再进业务；preload 不暴露原始 ipcRenderer。
3. **画面嵌入两平台不同构**：安卓 = scrcpy 协议流 + WebCodecs（全链路 MIT/Apache 可用）；iOS 无公开帧流 API，只能 ScreenCaptureKit 窗口采集——这是两平台能力差异最大的点，编排层需按平台适配。
4. **平台门控**：iOS 功能仅 macOS 且依赖本机 Xcode（runtime 不可随 App 分发，只能检测/引导安装）；安卓依赖 SDK 四件套（可引导下载到独立目录）。
5. **资源量级**（调研实测）：Apple Silicon 16GB 每实例约 1.3GB RAM、约 150 进程 + 3000 文件描述符；10 台最优、14 台可达（需调系统 fd 上限）。
6. **验证手段**：`npm run typecheck` + `npm run lint` + `npm run test` 必过；行为验证走 `npm run dev`（renderer 交互可经 CDP 冒烟，视觉以截屏为准——learn 2026-10-01/2026-10-03）。
