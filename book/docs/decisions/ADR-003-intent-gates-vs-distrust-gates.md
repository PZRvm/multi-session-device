# ADR-003：把意图关卡和不信任关卡分开

## Status

Accepted——2026-09-14 在强模型工作流校准中落地。修改 ADR-001 的 Phase 2 关卡；六阶段结构本身不变。

## Context

工作流的关卡写于 agent 模型还需要硬护栏的年代：无差别通读、规定步骤顺序、为确认而停车。强模型翻转了这账——OpenAI 的 [Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra) 记录了这个转变：曾经帮弱模型的脚手架，现在造成错误路由、消耗上下文、过早停车，以及拦下环境本就允许的动作的审批。

关卡的 justification 是混的。有些存在，是因为决定权在人（review 完整性、作用域纪律、生产安全）。有些存在，只是因为弱模型信不过（一刀切的设计确认、规定的编码循环、运行前先问）。只有第二种随模型能力老化。

## Decision

关卡按理由分类，每类有不同的维护方式：

- **意图关卡——保持硬，与模型无关**：Phase 5/6 只记录不修复（review 必须 review 建出来的东西）；Phase 3 作用域纪律；生产和凭据安全；`main` 只合并不直推。
- **不信任形态的规则——降级为默认**：Phase 4 的红-绿-重构循环是默认路径；强制的是关卡（全绿、不削弱断言、覆盖矩阵）。guideline 阅读走指针制（`guidelines/README.md` 的输入表），永不通读。
- **确认关卡——改为缺口制停车**：Phase 2 产出完整设计并推进到 Phase 3；只在真实缺口处——作用域冲突、数据形态未定、外部依赖不清——为用户停下，绝不只为确认而停。
- **权限翻成授予**：本地命令预批准（AGENTS.md 的默认安全一节）；agent 直接跑、修、再跑，不用问。
- **plan 带明确的完成标准**——防止过早停车的终点线。
- **常效重新审计**：agent 的模型世代更换时，对照这套分类学重新审计 AGENTS.md、`guidelines/` 和 skills。

## Consequences

- 强 agent 不再为预批准的动作和确认停车；弱一点的 agent 从 plan 拿到一条明确的终点线
- 人的评审点从"任何代码存在之前"挪到"交付的设计加上记录的 review"——每个功能更便宜，但错误的设计方向会在实现之后才暴露；Step 0 和需求 brief 承载更多意图分量
- 弱模型丢了一些护栏——钉在弱模型上的项目可能想要更严的措辞，应该写进自己的 ADR
- 重新审计规则是 recurring 的维护任务；跳过它，不信任关卡就会悄悄长回来
