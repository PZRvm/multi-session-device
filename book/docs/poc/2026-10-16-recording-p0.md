# 录屏 P0：媒体可行，整道门槛尚未通过

本页记录 [录屏 plan](../../plans/2026-10-16-device-recording.md) 的先行 P0 批次：当时只实现独立探针，未接正式录制入口、未修改 `src/`、产品依赖与已有设备配置。后续正式代码和最新验证另见 [实现验证](2026-10-16-recording-implementation.md)。

结论：MP4、最大画布与双设备采集有实际产物；**原设计直接保留 AAC PTS 未过长录同步门槛**。保留共同起点、用 AAC 采样数推进的候选修订有改善；修订仪器后旧 A/B 样本为 46/120ms，不能标全部通过。但当前连接真机为 Android 12，缺 Android 13+ 真机声音验证，也未完成正式任务生命周期/触控延迟测量。P0 不标全过。2026-10-16 用户批准依据模拟器结果继续实现，Android 13+ 真机音频验收后移到交付前，其余性能与生命周期项随正式实现补验。

## 环境与方法

- macOS 15.8.1、arm64、32GiB RAM。
- npm lock 安装的实际 Electron **39.8.10**、Chromium **142.0.7444.265**；不把 package.json 的最低版本当本机版本。
- scrcpy-server **3.3.3**（现有 SHA-256 校验）；Mediabunny **1.61.5**，隔离 npm 目录安装，产品 package/lock 未变。
- 两台专用临时 AVD：API 36 google_apis arm64，1080×2400，host GPU、2 核/2048MiB、无头冷启动，独立 AVD_HOME。
- 真机：同一台荣耀 EBG_AN00，SDK 31；USB 与 Wi-Fi serial 对应同一实体，实测物理标识一致。只持久化能力与格式，不保存真机屏幕像素。
- 测试源为自建 `com.foreunit.recordingpoc`：移动色条、20 秒横竖屏轮换、2 秒周期闪光与短音；闪光以 AudioTimestamp 的实际播放时钟校准。
- ffmpeg/ffprobe 仅为独立测试仪器，不成为应用依赖。同步结果以 10ms 分辨率采样闪光/脉冲，测量脚本与测试源都在 [探针目录](../../../scripts/recording-poc/README.md)。

两流各约 620 秒的音频原始 PTS 跨度，与 `(AAC 包数 - 1) × 1024 / 48000` 的采样跨度分别相差 **319.140ms / 413.752ms**。原始 PTS 也有 201/237ms 级间隔，不能只凭 PTS 跳变断言 TCP 丢音频包。

候选修订保留首音频 PTS 与视频的起点关系，后续按采样数推进；不以收包时间替代媒体时钟，也不为不同测试文件硬减一个固定延迟。结果改善支持“连续 AAC 的包 PTS 与实际采样时间需要分开处理”的设计，但不证明所有系统/编码器/静音中断都能照搬。Android AudioRecord 的具体时钟/缓冲来源仍需真机对照，不对上游或硬件直接定责。

补充来源：[3.3.3 AudioRecordReader](https://github.com/Genymobile/scrcpy/blob/v3.3.3/server/src/main/java/com/genymobile/scrcpy/audio/AudioRecordReader.java) 同时使用 AudioRecord timestamp 与估算；[AudioPlaybackCapture](https://github.com/Genymobile/scrcpy/blob/v3.3.3/server/src/main/java/com/genymobile/scrcpy/audio/AudioPlaybackCapture.java) 约束 Android 13+。查看 master 的 reader 仍有同类处理，不能把“升级 server”当已经验证的修复。

## 仪器修订（正式集成阶段）

原 PCM 管道不保留解码音频帧 PTS，可能遗漏音频轨道启动偏移与合法间隙；停止边界截断的最后脉冲也不能与前一个两秒前事件配对。正式集成阶段的 `measure-sync.mjs` 改为按 ffprobe 解码帧 PTS/样本数定位音频事件，并只配对两轨均完整的可观察窗口；目标仍为 100ms。

复验原文件：A 末段原始 PTS 362ms、采样时钟 46ms；B 中段原始 235ms、采样时钟 120ms。上方表格保留当时仪器结果，不代表新口径下候选全部通过。后续正式管线短录为 72/79ms、十分钟为 112/106ms，仍未全过；真机音频按用户批准后移，详见实现验证报告。
