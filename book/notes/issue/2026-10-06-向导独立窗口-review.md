# 向导独立窗口分支 review 发现（只记录，未修复）

**范围**：`feature/wizard-independent-window` 相对 532f7da 的 5 个提交（1c17476 独立窗口 / 2a13843 去标题条与 X / 6e9e233 垂直共线 / 153820f 水平居中 / 0206f7c 三灯 y 回 12）。

## 待修（小）

1. **注释腐化：三灯 y 值过期**——`DeviceWizard.tsx` Header 注释写「与三灯 y=14 共线」，但 0206f7c 已把 `wizard.ts` 的 y 改回 12。注释与实现矛盾，误导后来者。
2. **注释腐化：WizardApp 仍称「模态窗」**——`src/renderer/src/wizard/WizardApp.tsx` 顶部注释「新建设备模态窗的页面根」；本分支已改非模态独立窗口（plan 与 DeviceWizard 的 Esc 注释都改了，漏了这处）。
3. **HTML 嵌套不合法**——`TitleGroup = styled.span` 内含 `<h3>`（span 只许 phrasing content，h3 是 flow content）。浏览器容错渲染无碍、a11y 树不受影响，语义上应为 `div`。BoardHead 存在 span>button 同类先例（历史模式，可一并清理）。
4. **dead CSS**——Header 残留 `gap: 8px`（唯一 in-flow 子元素是 TrafficSpacer，gap 已无作用）与右侧 `padding: 14px`（右侧无内容）。无害。

## 修复记录

2026-10-06 用户裁决修复「待修（小）」全部 4 项（提交见 git log）：注释腐化 ×2（Header y 值、WizardApp「模态」措辞）、TitleGroup span→div（附嵌套合法性注释）、Header dead CSS（去 gap、padding 收窄为仅左侧 14px——左侧保留是为了把 no-drag 让位区对齐三灯灯组）。修复后 274 测试全绿、typecheck/lint 0 错，CDP 居中冒烟零漂移（组中心 450.0、垂直 19.5 共线）。决策项与备查项维持原状。

## 决策项（不阻塞，跨平台时再议）

5. **非 darwin 标题双显**——win/linux 保留系统标题栏（窗口 title「新建设备」），应用内 Header 又渲染居中的「新建设备」。当前需求全部以 darwin 为准，不阻塞；将来跨平台时需决策（非 darwin 隐藏 Header 标题，或同样 hiddenInset 化）。

## 备查（无需行动）

6. **closeWizardWindow 无单测**——main 进程 BrowserWindow 在 vitest/jsdom 无法实例化，现有测试体系覆盖不了；由 CDP 真机冒烟覆盖（plan 实现记录有证据）。
7. **open 互斥兜底的既有边界**（分支前已存在）——load 失败且无人关窗时窗口永久隐藏、`opening` 卡 true，后续 open 永远静默返回。`closed` 事件兜底复位的设计在 issue 2026-10-04-wizard-window-singleton-race 已有记录。

## review 通过面（摘要）

生命周期链路闭合（主窗 closed → closeWizardWindow 判 isDestroyed → wizard closed 复位引用与 opening）；`wizardWindow = window` 构造后同步赋值、主进程单线程无竞态窗口期；`wizard:close` sender 守卫与 `wizard:open` 父窗解析失败即抛错保持原语义；TrafficSpacer aria-hidden + Esc/底部取消键盘可达（测试 364/370 行覆盖），移除 X 无 a11y 回归；`window.api?.platform` 可选链兼容 jsdom；darwin 三灯参数带实测注释；三层视觉证据（DOM 断言 / Quartz 单窗像素 / 视觉分析）居中差 0.0px。
