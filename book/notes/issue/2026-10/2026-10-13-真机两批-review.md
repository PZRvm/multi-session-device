# 真机两批 code review 发现清单（Phase 5，只记录不修）

范围：`git diff dev..HEAD -- src/`（plan 2026-10-13-real-device-usb-and-apk-install 与
plan 2026-10-13-real-device-toolbar-parity 全部改动 + 三次热修复）。总体结论：**pass，
无 P1**——协议/契约/分层与既定模式一致，测试覆盖主干完整。

## P2（1 项）

- **P2-1 取消退出后真机跟踪永久停止**。[main/index.ts](../../../../src/main/index.ts)
  before-quit 序列里 `stopExternalTracking()` 在 leftovers 检查**之前**执行；用户在
  「仍有实例在跑」对话框选择留下（`resumeAfterShutdown()`）时，track 客户端已销毁且
  `registerExternalIpc` 的 `if (deps) return` 幂等守卫挡住重启——真机列表从此失联直到
  应用重启。修法方向：把 stopExternalTracking 挪到「确认退出」分支（quitGuard 置真
  之后），或给 external 域加 resume 接缝对称恢复。

## P3（8 项）

- **P3-1 未使用词条 `realDeviceSection`**。头部实际用的是 `realDeviceSectionCount`；
  `realDeviceSection` 三语各一条无引用（satisfies 只锁键集不查使用）。
- **P3-2 LogcatApp 初始拆桶的 stale 条目**。按「runId 在场」拆 AVD/真机两桶：
  starting 态 AVD 行（runId 未发布）会误入真机桶并滞留到下一次对应流推送；
  running 过滤兜底不显示，无用户可见影响，但桶语义不纯。
- **P3-3 externalStore 网络态的迟到写回**。拔线触发的 `apply` 已 prune 死键，但
  在途 toggle 的读回确认仍会 `applyNetworkState` 复活该键，直到下一次全量 apply
  才清——瞬态孤儿键，无消费方读到错误态（画布已卸载）。
- **P3-4 真机未就绪的词条口径**。截屏/网络对 unauthorized 真机报
  「设备不在运行中」——语义对（不可操作）但文案偏 AVD；日志订阅报
  「设备未运行，无法订阅日志」同款。统一一条「设备未就绪」词条可解。
- **P3-5 ExternalCanvas 无组件级测试**。外框渲染、工具条无电源钮、「仍要安装」
  按钮点击链路均无直接测试（DeviceToolbar/DeviceListPane 层有覆盖，画布层空）。
- **P3-6 epochs Map 无界增长**。每个 serial 的连接代次只增不清（removed 后保留）；
  长会话多设备场景内存影响可忽略，语义上「代次单调」也依赖保留。
- **P3-7 parseTrackDevices 多词 state 的宽容映射**。老 adb 的 `no permissions (...)`
  态会被切成 state='no' → 映射 offline 显示「离线」；可接受但未在代码注释说明。
- **P3-8 选中互斥是呈现层而非双向清 store**。plan 字面写「组合层双向清」，实现是
  `selectedId` 传 null 的呈现互斥（deviceStore.selectedId 保留）——真机拔线后 AVD
  选择自动回位，体验更优；与 plan 措辞偏差记录在案。
