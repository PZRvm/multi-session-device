# 多 worktree 并行时 Electron dev 互相顶死（单实例锁共享 userData）

- 观察：2026-11-02，feature-screenshot-editor worktree 的 `npm run dev` 在另一 worktree（feature-windows-titlebar-adaptation）的 Electron 运行期间启动，vite 正常起在分配端口 6176，但 "starting electron app..." 后进程静默退出。根因：两个 worktree 同包名 `multi-session-device`，Electron `requestSingleInstanceLock()` 按共享 userData 判定，先启动者持锁；后启动者 `app.quit()` 无任何输出（src/main/index.ts:26-28）。端口隔离（create-worktree 技能的 MSD_DEV_PORT 方案）解决了 vite 冲突，但解决不了应用级单实例锁。
- 复现：worktree A 跑 `npm run dev` 并保持应用存活；worktree B 再跑 `npm run dev`——vite 起来、Electron 立即退出、无错误日志。
- 影响：多 worktree 并行开发的验收/联调只能串行；被挡的一方无明确报错，排查成本高（本次靠 `Get-Process electron` 按 Path 归属定位到另一 worktree 的持锁进程）。
- 建议方向：应用侧按运行环境区分 userData（如 dev 下 `app.setPath('userData', …+#<worktree 标识>)`，或 setAppUserModelId 带后缀）使单实例锁按 worktree 隔离——需评估对 locale/theme 等持久化存储的分裂影响；或 create-worktree/merge-worktree 技能层面提示「同一时刻仅一个 worktree 可跑应用」。至少给 `!gotSingleInstanceLock` 退出路径加一条 stderr 提示，避免静默退出。
