# 图片编辑布局复审发现

复审范围：`95bab52..ebbfd5a`，包含图片编辑布局、原生三灯高度同步、工作区端口配置，以及一并提交的 README。相关 5 个测试文件共 52 项通过。评审时以下问题均已复现，仅记录；后续按用户授权完成修复，结果见文末。

## P2：页面缩放后原生三灯与工具栏失去共同中线

- **位置**：`src/renderer/src/components/ScreenshotEditor/EditorWindow.tsx:107`、`src/main/window/screenshotEditor.ts:166`、`:172`。
- **复现**：macOS 打开 720px 编辑窗，使用默认 View 菜单的 Zoom In / Zoom Out。项目没有替换该菜单；快捷键拦截不禁用菜单中的缩放动作。隔离 Electron 验证加载实际编辑器和窗口控制器，以 setZoomFactor 设置相同的缩放结果。
- **观察**：100% 时高度 48、原生 y=16，中心一致。125% 时 DOM 高度约 68.8 CSS px，操作钮中心对应窗口坐标 42.5，原生 y=26、灯中心 33.5，偏上约 9px。随后缩到 80%，DOM 高度约 47.998，被 `height < 48` 拒绝，原生位置留在 y=26，偏下约 14.55px。
- **原因**：上报的是 CSS 像素高度，定位和窗口高度校验使用窗口 DIP；两者在非 100% 页面缩放时不同。浮点误差也会把合法的 48px 最小高度挡掉。
- **建议方向**：统一定位、校验和上报所用的坐标单位，考虑实际 zoomFactor，并处理尺寸浮点误差；覆盖缩放前后换行和恢复单行。现有 renderer 单测未走 macOS observer 路径，主进程测试仅注入整数高度。

## P3：显式端口覆盖仍被损坏的本地元数据阻断

- **位置**：`electron.vite.config.ts:9`。
- **复现**：在临时目录放入内容为 `{` 或 `null` 的 `.worktree.json`，设置有效的 `MSD_DEV_PORT=6180`，用 electron-vite 的 loadConfigFromFile 加载实际配置，分别采用 serve / build 模式。
- **观察**：有效元数据正常使用覆盖端口 6180；上述两种异常内容分别触发 JSON 语法错误或读取 null.port 的 TypeError，serve 和 build 均加载失败。未修改真实工作区的元数据。
- **原因**：配置模块无条件解析元数据，发生在环境变量优先级判断之前，且不区分开发与构建。显式覆盖无法绕过这份可选文件的故障。
- **建议方向**：只在需要自动端口时读取元数据，校验其结构并处理读取/解析失败；构建流程避免依赖本地调试端口元数据。


## 修复结果（2026-11-03）

两项均已修复。三灯定位由本窗 getZoomFactor 将 CSS px 转为 DIP，校验容纳亚像素误差；高度未变的缩放也继续上报。开发端口按需读取，优先有效环境变量，元数据异常或无效时回退 6174，build 不读取该文件。

真实 Electron 的 720px / 1280px 窗口在 100% → 125% → 80% → 110% → 100% 转换中均通过，最大中心差约 0.45 DIP；配置实际加载的 6 个场景通过。全仓 1560 项通过、6 项跳过，build、typecheck、lint 通过。实现与验收见[修复计划](../../../plans/2026-11-03-screenshot-review-fixes.md)。
