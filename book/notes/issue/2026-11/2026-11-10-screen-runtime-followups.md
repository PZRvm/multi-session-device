# 投屏重建修复后的现场待验证项

2026-11-10 已安装版 1.0.0 排查发现：模拟器 dumpsys input 有 128 个 Display 区块，其中 126 个提示 `No DisplayInfo found!`；logcat 有 114 条 Binder transaction failure，消息约 1.66–1.79 MB。磁盘仍余 1.3 GB。真机同时有两套应用启动的 scrcpy 进程及 forward。原始证据保存在本机 `/tmp/msd-investigation-20261110/`，临时目录不会长期保留。

[本次修复](../../../plans/2026-11-10-screen-reset-loop.md)通过代码探针证实并阻断正常静置后的误重建，限制连续恢复次数，但尚未验证失效显示条目的释放责任和真机重复会话来源，也没有清理运行设备的状态。

建议在允许中断设备时，对模拟器停止后冷启动、重新连接真机做前后对照，检查失效显示数量和重复会话是否归零，再持续观测滑动与设备切换。若残留仍增长，应单独验证当前 Android 镜像与 scrcpy 的虚拟显示释放。

安装版 stdout/stderr 指向 `/dev/null`，未找到应用诊断日志；现场每次 reset 的来源和 renderer 解码错误无法从历史记录确认。另立范围补充不含屏幕内容的结构化诊断，再区分拥堵、序号缺口、激活回放和录制请求。
