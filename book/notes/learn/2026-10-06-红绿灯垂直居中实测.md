# darwin 红绿灯垂直居中（实测结论与测量法）

**场景**：`titleBarStyle: 'hiddenInset'` + 自绘 40px 板头（BoardHead 模式），要求红绿灯在板头内垂直居中、与标题组共中线。

## 实测结论（2026-10-06，向导窗）

- 灯是 **12px 圆**；`trafficLightPosition` 的 y **不是**灯顶——有 **+2 内禀偏移**（code y=12 → 灯实际顶 14；y=14 → 顶 16）。
- 因此 **灯中心 = y + 8**。40px 板头（border-box 含 1px 底 hairline）中心 = 19.5 → **y=12 才居中**；y=14 会低 2px，肉眼可见（本文档就是踩了这个坑再测回来的）。
- 公式：`{ x: 14, y: 12 }` → 灯中心 19.5 = 板头中心 = 标题组中心（标题组由 CDP `getBoundingClientRect` 量得 19.5）。
- 主窗（y=12）实测本就居中——主窗没改过 y 却一直「看着对」，是因为它本来就是对的。

## 测量坑与可靠路径

1. **CDP `window.screenX/screenY` 在多显示器下不可靠**：窗口可能不在 `screencapture` 默认捕获的主屏上，区域截图按它裁会裁到壁纸。
2. **多 dev 实例并存时窗口互相遮挡**：全屏截图会读到别的实例的窗口像素（本仓库多 worktree 并行开发时是常态）。
3. **可靠路径——按窗口 ID 单窗截图**（pyobjc，位置无关、无遮挡、窗口局部坐标）：

   ```python
   Quartz.CGWindowListCopyWindowInfo(...)              # 按 kCGWindowOwnerPID + kCGWindowName 找窗
   wid = w['kCGWindowNumber']                          # 注意不是 kCGWindowWindowID（不存在）
   img = Quartz.CGWindowListCreateImage(
       Quartz.CGRectNull,                              # 必须显式传，None 会 depythonify 报错
       Quartz.kCGWindowListOptionIncludingWindow, wid,
       Quartz.kCGWindowImageBoundsIgnoreFraming)
   ```

4. **灯的像素检测阈值**：非关键态灯是**深灰圆**（深色主题 bg≈18 时 `35<v<220` 且三通道近等即命中；只测彩色会漏）；关键态彩色（`r-max(g,b)>40` 等）。逐行统计命中像素 ≥3 的行即灯行，行轮廓 12/24/30/30/36/36/… 是标准圆profile，可自证。
5. **主进程改动（BrowserWindow options）electron-vite dev 不会自动重启**：改完必须杀 Electron 重拉，否则量的是旧值（PID 不变 = 没重启）。
