# 设置静态前端的验收边界

- **适用场景**：先实现设置布局，业务配置与全应用 i18n 后续接入。
- **模型**：展示字段放在 renderer 的只读模型里，不提前扩充三进程契约。路径、版本和内存阈值缺数据就留空；样例不能写成检测结果。
- **副作用**：分类切换只改本窗状态。业务按钮、输入和选择器原生禁用；窗口桥只提供受 sender 守卫的 open/close。测试同时检查 disabled 状态和业务 API 零调用。
- **多语验收**：用同键字典与局部样例检查三语布局，英文长文案在最小窗下单独验证。样例入口只用于检查，完成后清理；正式全应用语言状态接入时提升字典，避免两份事实源。
- **截图验收**：先确认当前分类标题，再截图；原生事件与渲染帧可能不同步，文件名不能当作内容证明。本轮浏览器 fullPage 捕捉曾漏掉滚动容器内容，普通视口截图与 DOM 状态一致；无效证据应重新捕捉。Retina 像素尺寸与 DIP 分开记录，逐张打开确认内容与尺寸。
- **原生副本**：同机多个 Electron 副本共用 bundle id 时，按 app 路径绑定也可能落到另一进程。本轮用临时独立 bundle id 与隔离 userData 核查生产设置窗，退出后清理副本；绑定后仍先确认标题、file URL 和空设备状态。
