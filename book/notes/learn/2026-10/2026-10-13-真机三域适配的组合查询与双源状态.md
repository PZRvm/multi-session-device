# 真机三域适配的组合查询与双源状态

plan 2026-10-13-real-device-toolbar-parity 实现期确认的三个结论：

1. **组合查询模式收敛成两个函数就够**。第一批 serialOfDeviceId（throw 型）之后，三域
   只再需要 `deviceRefOfId`（async null 型——调用方决定文案）与 `isDeviceActiveOfId`
   （同步复核型）两种形态，覆盖了截屏/网络/日志的全部注入点。给「多来源设备」加域能力
   时，先看注入点的错误语义（throw / null / boolean），按语义挑形态，不要每域再造。

2. **跨来源的状态不能放进会 prune 的 store**。deviceStore 的 `network` 表在每次快照
   apply 时按 AVD 设备集 prune——真机键（serial）放进去会被下一次推送清掉。外部设备的
   网络态独立放 externalStore（apply 同步 prune 自己的键），消费侧（useNetworkSwitch）
   用 `externalStore[id] ?? deviceStore[id]` 双源合并读：两源 id 形态不相交（serial vs
   uuid），?? 合并安全，两个画布调用点零改动。判断标准：store 的 prune 谓词是否认得
   你的键。

3. **派生对象的生命周期跟随要比原始值 key，不比引用**。日志 dock 的「目标消失自动
   收起」原本靠 `logcatDevice !== prevLogcatDevice` 的引用比较（store 里的对象引用稳
   定）。真机分支把目标改成 `{ id, runId }` 派生对象后引用每帧新建，比引用会无限
   setState——改比 `${id}:${runId ?? ''}` 字符串 key。凡是渲染期 `adjust state during
   render` 模式（无 effect 的状态对齐），比较基准必须是原始值或稳定引用。
