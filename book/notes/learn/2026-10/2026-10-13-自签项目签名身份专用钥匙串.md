# 自签项目签名身份：专用钥匙串 + 分区访问控制

**背景**：无付费 Apple 开发者账号时 electron-builder 只能跳过签名或 ad-hoc。ad-hoc 的代价是**每次构建应用身份都变**——摄像头、辅助功能这类 TCC 授权升级即丢；且签名显示匿名。方案：自签一张项目专属证书（CN=multi-session-device，10 年），appId 从模板默认 `com.electron.app` 换成 `com.foreunit.multi-session-device`，afterPack 钩子里签。

## 三个坑（本条的核心价值）

1. **`security import -T /usr/bin/codesign` 在新 macOS 上不够**。导入时 `-T` 只是建议 ACL，真正拦截的是**分区访问控制**（partition list）：CLI 取用私钥一律 `errSecInternalComponent`，不弹窗、没法点。标准解法 `security set-key-partition-list -S apple-tool:,apple: -k <密码> login.keychain` 需要**登录钥匙串密码**——不该让用户把密码交给自动化脚本。
2. **解法：专用钥匙串**。`security create-keychain -p <自生成密码> msd-sign.keychain` → 导入证书 → 对这个钥匙串跑 set-key-partition-list（密码是自己设的，无障碍）→ `security list-keychain -d user -s login.keychain-db <专用钥匙串>` 挂进搜索列表。密码存 `~/Library/Keychains/msd-sign.pass`（600，不入仓库），构建钩子签名前 `security unlock-keychain -p "$(cat …)"` 解锁（重启/休眠后会自动上锁）。从此签名零交互、零弹窗。低风险合理：这把钥匙只在本机有效、只能签这个项目。
3. **弹窗风暴的成因**：私钥未授权时若在有 GUI 的会话里逐组件签名（--deep 要碰私钥几十次），每次都弹钥匙串授权框，点掉几十次或中途取消即整体失败——报错形如 `In subcomponent: …/Electron Framework.framework`。别指望点"始终允许"能救，直接上专用钥匙串。

## 验证身份是否真的稳定

看**指定需求**而不是 Authority 行（自签证书 `codesign -dv` 常不显示 Authority，是展示习惯不是没签上）：

```
codesign -d -r- <app>
designated => identifier "com.foreunit.multi-session-device" and certificate root = H"7402357d…"
```

DR 同时锚定 bundle id 和证书指纹——同证书同 id 的后续构建满足同一 DR，macOS 视为同一应用，授权保留。若 DR 里只有 identifier 没有 certificate（ad-hoc），身份就是漂的。

## 边界

- 自签只在本机有效：别的机器 Gatekeeper 照拦。要分发就得 Apple Developer ID + 公证（付费会员），届时 electron-builder.yml 配 `mac.identity` + 证书即可，钩子里的 ad-hoc 回退正好当无证书环境的兜底。
- appId 换名后 LaunchServices 视为全新应用：旧 bundle id 的启动台图标可能残留幽灵，长按删掉即可。
