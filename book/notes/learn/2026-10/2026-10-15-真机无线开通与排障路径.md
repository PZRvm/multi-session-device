# 真机无线调试：开通路径与排障谱系（荣耀 30 Pro 实测）

适用场景：给真机做无线 adb 接入（本仓 stage06 无线批）、排查「adb connect 连不上/offline」类故障。

## 开通路径分型（按机型）

- **荣耀/华为系（EMUI/Magic UI/HarmonyOS）**：系统**没有**「无线调试」开关（华为官方
  支持页 zh-cn15997564 明说「没有无线调试设置项」，荣耀俱乐部催更帖无果）——Android
  版本到 12 也没有，与版本号无关。唯一路径：插线 → `adb tcpip 5555` → `adb connect
  IP:5555` → 拔线。RSA 授权与 tcpip 模式都持久化在手机侧，只有**手机重启**才需再插线。
- **有官方开关的机型（小米/三星/原生等，Android 11+）**：全程无线——开关 → 配对码
  `adb pair` → connect；mDNS（`adb mdns services`）能发现。配对端口临时、≠连接端口。

## 排障谱系（按症状对号）

1. **connect 报 failed/offline，手机侧日志干净、无授权弹窗** → 大概率**代理 TUN 劫持**
   （Clash/Surge 虚拟网卡抢默认路由）。特征：`route -n get <手机IP>` 走 utunX/网关
   198.18.x；nc 探活「成功」是代理本地代答的假握手。**同网段免疫**——macOS 对 on-link
   流量走物理网卡直连路由，TUN 开着也不受影响。跨网段时二选一：TUN 加局域网绕行规则，
   或测试期关 TUN。程序侧对策：连接失败时查目标 IP 是否在本机网段前缀内，不在则给
   cross-subnet 提示（本仓 wirelessConnectFailureText）。
2. **`tcpip 5555` 后立刻 connect 失败** → adbd 重启竞态（数秒不应答窗口）。对策：退避
   重试（1/2/4/8/16s 共 5 拍）。顺序上**先读 IP 再 tcpip**（`adb -s S shell ip route` 解析
   wlan0 的 `src <ip>`），避免重启窗口干扰 shell。
3. **长时间息屏后设备消失（ping 全丢、ARP 仅残留）** → 荣耀省电深睡挂起 Wi-Fi，非
   tcpip 失效——亮屏即回，`adb connect` 直连即恢复，**不需要插线**。缓解：睡觉时给手机
   插充电器（充电态不休眠 Wi-Fi）。
4. **「同一个 Wi-Fi」≠ 同一网段**：手机 192.168.0.x、Mac 192.168.31.x 这种双路由场景，
   无线调试不可能通。查法：两侧各看默认网关网段。程序侧同上走 cross-subnet 提示。

5. **网段扫描扫出「幽灵候选」**（2026-10-15 无线批实测）：本机存在 TUN 虚拟网卡
   （198.18.x/30）时，扫描其网段会得到代理的**假应答**——列表出现 198.18.0.7 这类
   幽灵设备。对策：网段采集按接口名整族排除虚拟接口（utun/tun/tap/awdl/llw/bridge/
   veth/vmnet/docker…，本仓 `isLanInterface`）——物理网卡之外只扫得出鬼。

## mDNS 解析防坑

`adb mdns services` 输出行里**实例名可含空格**（同族坑见 flutter#187092），解析必须按
服务类型子串（`_adb-tls-connect._tcp` / `_adb-tls-pairing._tcp`）匹配行 + 行尾
`ip:port` 正则提取，绝不按空白切整行。老版本 adb 只打端口不打 IP——无地址行只能丢弃
（没有 host 无法自建连接），手动输入兜底。
