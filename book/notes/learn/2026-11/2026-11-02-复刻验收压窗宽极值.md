# 复刻验收要压窗宽极值：V8 竖屏通过 ≠ 360px 极小窗通过

- **Scenario**: 截图编辑器复刻验收 V8 明确含「竖屏」用例且通过，但用户实测仍报窄窗工具条堆叠、文字钮破版。
- **Why**: 窗口尺寸自适应算法是 `min(1, 可用宽/图宽, 可用高/图高)` + `MIN_WINDOW_WIDTH=360` 下限——竖屏手机截图（如 1080×2400）在常见显示器上算出约 551px 窗宽，**验收看到的正是这个典型值**；而小屏笔记本或更窄的截图源会把窗宽压到 360px 下限。源 CSS 是单行不换行 flex（按钮 `flex:none`、文字钮无 `nowrap`），内容宽约 590px：551px 差一点能挤下、360px 必然溢出堆叠。jsdom 断言不了 flex 溢出，POC 截图又恰好停在典型尺寸——两道验收都没拦住。
- **怎么做**: 凡是「窗口尺寸随内容自适应 + 有 MIN 下限」的功能，视觉验收必须**显式取 MIN 宽/高极值**（可直接把窗拉到最小，而不是只看算法算出的典型值）；布局类修复用真实浏览器（Edge `--headless --screenshot` + 页内脚本量包围盒断言重叠/溢出）按 360/448/551/800 五档复核，不依赖 jsdom。修复取向：flex 工具条溢出的正解是**按组原子换行**（组容器 `flex:none` + 容器 `flex-wrap` + `row-gap`），不是横向滚动或压缩控件。
