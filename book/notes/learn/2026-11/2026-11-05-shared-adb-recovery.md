# 应用重启不会自动刷新共享 ADB

- **场景**：无线连接持续失败，但 USB 或独立 TCP 探测正常；重启应用无效。
- **证据**：本次共享 ADB 自 11 月 3 日运行，重启应用未更换进程；11 月 5 日重启服务后手机 connect/shell 恢复。失效底层原因仍未确定，不能把进程年龄当作判据。
- **怎么排查**：分开验证手机监听、独立 TCP、共享 ADB connect、transport 和 shell。权限归属可能因进程启动方不同而不同，终端探测成功不能直接证明应用权限正常。
- **怎么恢复**：共享服务重启须说明所有设备/IDE 会受影响；预留互斥与执行门分开，确认后再查任务；诊断本身也遵守迁移门。重建投屏时保留活动 viewToken，日志订阅恢复要保持序号唯一，并等待真机新 track 代次。
- **worktree 调试**：不创建模拟器也不代表可以共写 userData；偏好、录屏恢复、设备对账仍可能写盘。可以共享 SDK 并隔离轻量运行数据。临时调试绕过单实例锁须在最终门禁前还原并确认 diff 为零。

## 复审修复补充

- 二进制截图执行器独立于普通 runAdb，也必须接共享执行门。命令超时返回结果不代表子进程已关闭，pending 应到 close/error 才幂等释放。
- 恢复门的拒绝检查要放在日志会话写表之前，否则临时 busy 会被缓存为长期 spawnError。
- 同窗口并发请求的完成顺序不等于用户操作顺序；不要在旧请求完成时按窗口清掉较新的诊断凭据。沿用有界的独立 attempt 即可。
