# 无线 scrcpy 熄屏停帧与建流泄漏谱系（SM-A155F 实测）

适用场景：排查「无线画面连接失败 / 画面冻结 / 卡顿」类问题；设计涉及 scrcpy 会话生命周期的功能。

## 事实谱系（按排查顺序）

1. **熄屏 = 零帧**。scrcpy 表面编码器在熄屏(doze)时零帧输出（实测熄屏后 57.7s 无任何包）；
   `power_on` 默认 true 只在连接时点亮一次，屏幕超时（A15 30s）后再次熄屏 → 画面冻结在最后一帧
   （session 仍 ready，无错误）。且 **resetVideo 熄屏下产不出新帧**——恢复链（3×3s resetVideo）
   在熄屏场景必然超时报 screenRecoveryTimeout。治理：打开视图/恢复节拍时 `input keyevent 224`
   唤醒（不解锁）。
2. **建流失败 = 泄漏**。`establishTransport` spawn 之后任何一步失败（forward 失败 / 15s video
   socket 预算超时 / 中途 abort），`session.transport` 都还没赋值，lifecycle 的 teardown 不会跑——
   serverProc（本地 adb shell + 手机端 app_process）+ forward 规则全部泄漏。失败一次留一个孤儿，
   「失败→点重试」每点一次多一个（实机曾同时 3 个孤儿 server + 4 条遗留 forward）。
3. **无线闪断 = 全量重建**。无线 adbd 传输闪断时设备 offline→track 重连首帧强制重建全部会话
   （runId 自增），重建窗口内 adbd 仍在恢复窗口，建流竞态失败率上升。16:11 实测一次闪断重建成功，
   证明失败是间歇性的；每次重建都是一次「画面掉线重连」体验。
4. **链路基线（判断"卡"先量链路）**。SM-A155F@5GHz RSSI -49dBm 链路速率 390Mbps；adb RTT ~50ms；
   push 4.4MB/s、pull 3.9MB/s（≈31-35Mbps，adbd TCP 管道实测上限）；scrcpy server 冷启动 1-2s
   （dummy byte 靠 1s 轮重试收敛）；帧流内容驱动（静止时零帧），活动时 ptsDelta≈100ms。
   8Mbps 目标码率 + i-frame=1s 对该管道够用——「无线必卡」先查链路基线再谈参数。

## 排查工具

复刻 transport 时序的探针（push→spawn→forward→1s 轮 dummy byte→控制口→元数据→测速）写在
`/tmp/scrcpy-probe/probe2.mjs`、`probe3.mjs`（会话消失即失效，写法记录在 plan 的 test plan）。
