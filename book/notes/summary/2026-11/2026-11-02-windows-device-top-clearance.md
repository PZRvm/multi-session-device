# 手机顶部避开窗口控件

> 最新修订：用户要求间距更近，已将外层留白从 40px 改为 20px，常规竖屏实际间距从 28px 收紧为 8px。下方保留首轮修复记录，最新验证见文末。

## 背景

用户提供的真机截图中，Logcat 图标压到手机外框顶部。用户要求手机顶端低于图标和功能区，放不下时缩放手机，保留此前取消独立通栏的布局。

## 做了什么

仅在 Windows 的 canvas-content 增加 40px 顶部 padding。画布、列表、分隔条仍从原顶边开始，设置窗、Mac/Linux 和窗口按钮没有改动，也没有增加顶部行。

DeviceCanvas/ExternalCanvas 在缩小后的内容盒内布局，现有 ResizeObserver 和等比算法自动适配；视频、外框、皮肤和输入映射继续共用 stage，没有改动解码或坐标算法。

## 为什么这样选

根因是投屏可用高度包含了顶部按钮区。修改外层提供的空间即可让既有布局生效，无需分别调整真机、模拟器与皮肤，也无需只移动手机而让底部溢出。

## 结果

- 修复前先用真实 Electron 的 ready 格式 fixture 复现失败：900×670 窗口，通用外框 y=28、height=562，进入约 40px 的顶部控件区。
- 修复后同一窗口 y=68、height=522，保持视频比例，外框底边仍为 y=590。850×480 短窗下外框 y=68、height=332，底部工具条仍在窗口内。
- 100%/125%/150% Electron 设备缩放各 25 项通过，renderer 错误采集均为空。包含模拟器、真机竖屏/横屏、短窗、dock、主题、语言和窗口状态。图片与原始结果位于本地 `dist/windows-device-clearance-check/after/scale-{1,1.25,1.5}/`。
- 组件与几何测试五文件 64 项通过，typecheck、lint、格式和生产构建通过。新增规则是局部 CSS，未添加重复 CSS 字面量的单测；行为由真实排版中的外框边界、比例与尺寸断言验证。
- 独立只读评审通过，未发现新增缺陷。

## 验证边界

真实窗口使用隔离用户目录和模拟的 ready 流格式，未连接或操作用户设备，也未验证真实视频解码与鼠标/触摸输入。皮肤沿共用布局并通过现有几何测试，未逐个真实皮肤截图验收。Mac 仅验证平台条件，未真机复验。

125% 的首次短窗检查曾在 ResizeObserver 提交前读取旧的手机尺寸；辅助验证改为有超时的条件等待，仍检查同一最终几何边界，后续 25 项通过，生产代码未增加等待逻辑。

改动留在 `feature/windows-titlebar-adaptation`，未合并或推送。[计划](../../../plans/2026-11-02-windows-device-top-clearance.md)已完成。

## 间距收紧修订

用户确认交互正常后要求约 8px 间距，只有原本已是 8px 时才改为 4px。实测原外框 top=68、功能区 bottom=40，间距 28px，因此目标为 8px。

仅将 Windows canvas-content 的 padding-top 从 40px 改为 20px，减去重复叠加的留白。常规档外框 top=20+16+12=48，距功能区 8px；默认竖屏外框高度从 522 增为 542，底边保持 y=590。未改 Mac、设置窗、窗口按钮、比例或交互逻辑。

先用严格的 8px 几何断言确认旧值失败（实际 28px）。修订后 100%/125%/150% 各验证模拟器竖屏、真机竖屏和短窗三个场景，九项间距检查均为 8px，renderer 错误为空。原始结果和截图位于本地 `dist/windows-device-spacing-check/scale-{1,1.25,1.5}/`；宽度受限画面仍按原规则居中，可有额外留白。

类型检查、lint、格式和生产构建通过；只读复核未发现问题。本轮只改一个 CSS 数值，采用真实排版验证，没有新增重复 CSS 字面量的单测。真实鼠标/触摸和 Mac 真机限制与上文一致。
