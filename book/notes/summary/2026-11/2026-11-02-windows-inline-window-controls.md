# Windows 控件回到原分栏

## 背景

首轮把原生按钮安全区做成了独立的全宽顶部行，改变了原分栏格式。用户明确要求取消这行：主窗图标、标题和原有操作都放在左侧列表内，右上直接放窗口按钮及左边的 Logcat；设置窗也采用同样方式。

## 做了什么

- 主窗移除 windows-header 与 workspace，恢复原横向分栏。BoardHead 回到 list-pane，画布和分隔条从 y=0 开始。
- Windows Logcat 用绝对定位依照原生按钮安全区放在全窗右上。日志 dock 仅局部避让工具栏，录屏反馈也只在画布内局部避让；其余正文不整体下移。
- 设置图标与三语“设置”进入左侧 nav；右侧详情和导航均从 y=0 开始。透明拖拽区域不占排版、不绘制背景或边线。
- 延续窄窗安全区避让、透明图标和原生窗口能力。主进程、IPC、设备/日志业务、Mac/Linux 的视觉布局没有改动。

## 为什么这样选

窗口控件占用的安全区只影响局部位置，无需成为独立布局行。让左栏标识归左栏、窗口按钮归窗口右上，能保留用户原来的工作台格式。

## 结果

- 先更新结构断言并确认旧布局失败，再修改实现。相关三个组件文件 65 项通过；加上向导/对账主窗回归，共五文件 76 项通过。typecheck、lint、生产构建和格式检查通过。
- 真实 Electron 39.8.10 使用隔离用户目录与设备 fixture，100%/125%/150% 各 23 项检查通过，renderer 错误采集均为空。验证包含画布/nav/详情的 y=0、左侧标识归属、没有独立 header、dock 展开、三语、主题、窗口状态和 500px 主窗 / 420px 左栏安全区。
- 900px 内容窗下 Logcat right=754，安全区 right=764；三档均保持 10px 间距。设置标识 x=0、y=0，位于 nav 内。
- 已查看主窗、dock 展开、设置窗的原生窗口截图，确认没有全宽顶部横线或单独顶栏。证据位于本地 `dist/windows-inline-controls-check/fixed-narrow-{1,1.25,1.5}/`，不入库。
- 独立只读评审通过，未发现确定性新增缺陷。

## 验证限制与后续

透明拖拽命中区与正文顶部 40px 重叠；实际投屏上缘、分隔条顶端和原生按钮的鼠标命中仍需人工核验，连接中 fixture 不能证明这些操作。桌面操作工具此前 native pipe 不可用，本轮未宣称验证真实鼠标拖动或 Windows 贴靠悬停；Mac 没有真机复验。

测试先行的失败批次还出现一次既有日志收起测试的时序抖动，之后两轮 65/76 项通过。本轮未改该用例的行为断言，现象补录在[既有问题](../../issue/2026-10/2026-10-13-AppLogcatDock测试偶发抖动.md)，不据此宣称已修复。

改动继续留在 `feature/windows-titlebar-adaptation` 工作区，未合并或推送。[本轮计划](../../../plans/2026-11-02-windows-inline-window-controls.md)已完成。
