# Windows 顶部适配

## 背景

Windows 原系统标题栏独立于应用操作区。用户要求移除这条标题栏，将透明图标与标题放在左上，原生窗口按钮放在应用右上，Logcat 开关紧邻按钮左侧；设置窗同样处理，macOS 保持现状。

## 做了什么

在 `feature/windows-titlebar-adaptation` 工作区实现。基分支 `dev`，开发端口 `6175`。主窗和设置窗仅在 Windows 使用 hidden 标题栏与 40px 原生按钮覆盖层；主窗顶部横跨设备列表、画布和日志栏。设置窗开启 Windows 最小化/最大化，沿用现有透明图标和三语标题。

覆盖层底色与符号色从主题 token 派生，随主题模式、主题色和系统外观同步。仅登记这两个目标窗，不影响其他子窗。日志处理函数、录屏业务和 IPC 契约没有变化。

## 为什么这样选

原生覆盖层继续承担窗口控制，避免增加自绘按钮和控制 IPC。安全区使用 Electron 提供的几何信息，Logcat 的定位独立于画布与 dock。

## 首轮结果

- 先新增失败测试，再实现。定向六文件 107 项通过，typecheck、lint、生产构建通过。
- 扩展回归 149 项中 148 项通过。主题 store 的写盘测试把路径写成 `/userdata/theme.json`，在 Windows 实际得到反斜杠路径；同一失败在原始 dev 复现，未修改该范围外测试。
- 使用真实 Electron 39.8.10、生产 renderer/preload 和实际建窗函数，隔离用户目录并注入设备快照，避免启动或操作用户设备。100% / 125% / 150% Electron 设备缩放各 22 项通过，含顶部几何、dock 展开、三套主题亮暗、三语、最大化/还原、最小化/恢复与 API 关窗。三次 renderer 错误采集均为空。
- 原生窗口截图确认透明图标、标题和三个窗口按钮；900px 内容窗下安全区右缘 764px，Logcat 右缘 754px，保持 10px 间距。证据保存在本地 `dist/windows-titlebar-check/{native,scale-1.25,scale-1.5}/`，不入库。
- 独立评审发现一项 [P2 窄窗问题](../../issue/2026-11/2026-11-02-windows-titlebar-narrow-window.md)，500px 主窗与 420px 左栏组合已复现。阶段 5 只记录，随后另开修复轮次。

## 验证限制与后续

桌面操作工具的 native pipe 两次连接失败，未验证真实鼠标拖拽、原生按钮点击命中和 Windows 11 贴靠悬停菜单。最大化/最小化等状态通过 Electron API 验证；显示缩放通过 Electron 设备缩放验证，没有更改系统显示设置。macOS 仅验证平台分支与既有交互测试，未在 Mac 真机复验。录屏反馈、外部设备和弹出/贴回规则沿原逻辑，部分通过组件测试覆盖，没有操作真实设备。

## 最终结果

[窄窗修复轮次](../../../plans/2026-11-02-windows-titlebar-narrow-window.md)完成：左侧顶部区域允许收缩，右侧为 Logcat 至少保留 40px。原 500px 主窗 / 420px 左栏场景，100% 下安全区 right=364、Logcat right=354；125%/150% 下分别为 365 与 355。修复后三档各 23 项检查通过，renderer 错误采集为空；证据位于本地 `dist/windows-titlebar-check/fixed-narrow-{1,1.25,1.5}/`。独立复审确认原 P2 解决。

相关测试在并行复验中暴露一个既有时序问题：日志 DOM 消失后，解锁窗口宽度的 effect 可能尚未执行。断言改为等待原来的解锁预期，未改变业务行为。更极端窄窗配合英文和宽左栏的内部控件布局是待核验建议，没有记录成已确认缺陷。

主计划已完成。工作区尚未合回 dev，也未推送；Mac 真机、鼠标命中、拖动和贴靠悬停等限制仍按上文保留。
