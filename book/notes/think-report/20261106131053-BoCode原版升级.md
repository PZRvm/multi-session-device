# BoCode 原版升级调研报告

> 创建时间：2026-11-06 13:10:53（Asia/Shanghai）
> 需求来源：将项目中文改编版 BoCode 换回官方原版，并同步官方更新。
> 调研单元：1 个
> 状态：用户已确认并实施；结果见 2026-11-06 升级计划与功能报告

## 1. 需求理解

### 1.1 功能目标

让后续会话使用官方原版四个 skills 和最新工作流，避免中文改编版与官方规则继续分叉。升级后能够从提交 SHA 识别基线、继续更新。项目源码布局、应用行为、发布流程和已有知识记录保留。

本轮仅查明差异并形成迁移建议，不修改应用代码或现行规则。

### 1.2 未知点清单

- [x] 官方有哪些更新？见 2.3，已读取官方 CHANGELOG、UPGRADE、ADOPT 及四技能入口相关文件。
- [x] 现有版本有哪些差异？见 2.2，既有语言改编，也有项目定制与旧规则冲突。
- [x] 能否整包覆盖？不能；官方升级指南明确区分模板文件与项目文件，见 2.4。
- [x] 迁移是否涉及历史文档？涉及 issue/task 状态元数据，正文与文件位置保留，见 2.5。

### 1.3 拆分判断

整体作为一个工作流迁移单元，skills、规则和索引必须一起升级，避免相互引用旧规则。

## 2. 调研单元：官方工作流迁移

### 2.1 该部分要做什么

替换本地中文四技能，合并官方规则和索引更新，建立升级版本记录。排除应用功能修改、历史文档翻译、源码搬迁、发布方式调整及自动推送。

### 2.2 项目现状

- `.agents/skills/bocode-{bocode,boscope,book-writeback,bowrite}/SKILL.md` 是中文改编版；名称也带本地前缀。这些目录被 `.gitignore` 排除，不在 Git 跟踪中。
- `.codex/skills/bocode-*` 是四个零字节普通文件，不是技能目录，不能作为有效技能副本。
- 中文 boscope 仍要求 Phase 2 等待批准，但 `AGENTS.md`、`book/guidelines/workflow.md` 与 `book/docs/decisions/ADR-003-intent-gates-vs-distrust-gates.md` 已采用真实缺口制。官方最新 boscope 与项目现行规则方向一致。
- 根目录没有 `.bocode-version`，需按官方无基线流程逐项合并，首次写入明确 SHA。
- `scripts/gen-book-index.mjs` 有本地必要改动：根目录布局、自定义分类、Windows 路径归一、CRLF 解析及 `--check`。`scripts/check-book-clean.mjs` 依赖 `--check` 检测索引新鲜度。不能直接换成官方脚本。
- issue 共 123 篇：47 resolved、10 open、9 closed、1 monitoring、56 缺状态；task 共 2 篇：1 completed、1 缺状态。按官方有效值，68 篇需要补充或转换。
- `book/guidelines/git-workflow.md` 包含本项目安装包发布机制。`AGENTS.md` 约定源码位于 `src/`、命令在根运行、changelog 未启用。以上不能被模板默认值覆盖。
- BoCode 版权及 MIT 许可已在 `THIRD_PARTY_NOTICES.md`、`licenses/BoCode-MIT.txt` 中保留。

### 2.3 候选方案

**方案 A：按官方 UPGRADE 合并，四个 skills 使用官方原文（推荐）**

官方基线：`79426a98a0fbf58d04f3c19a23a6a680343b24f7`，dev 分支，核查于 2026-11-06。已克隆完整历史；该 SHA 是此次观测基线，不代表未来最新版本。

来源：[UPGRADE](https://github.com/Focus695/BoCode/blob/79426a98a0fbf58d04f3c19a23a6a680343b24f7/UPGRADE.md)、[CHANGELOG](https://github.com/Focus695/BoCode/blob/79426a98a0fbf58d04f3c19a23a6a680343b24f7/CHANGELOG.md)、[ADOPT](https://github.com/Focus695/BoCode/blob/79426a98a0fbf58d04f3c19a23a6a680343b24f7/ADOPT.md)。

本次需要同步的变化：

| 官方变化 | 本项目接入点 |
| --- | --- |
| S/M/L 任务分级，小改走轻量流程 | 新增 task-tiers，合并 workflow、入口和评审规范 |
| Step 0 质疑继承假设，按实际约束设计 | 原版 boscope 与 workflow |
| 设计包含默认值、空状态、错误提示等体验 | 原版 boscope 与 review-checklist |
| Phase 2 只在真实缺口处停止 | 替换旧中文 boscope，保持现行项目语义 |
| bowrite 写作规则覆盖改写，保护条件与例外 | 原版 bowrite、writing-style、writeback 和文档模板 |
| task/issue 按状态归档，不移动文件 | 索引合并及 68 篇元数据迁移 |
| SHA 版本戳与升级指引 | `.bocode-version` 及项目升级入口说明 |

**方案 B：完整覆盖模板文件和工具**

来源为同一 [官方模板](https://github.com/Focus695/BoCode/tree/79426a98a0fbf58d04f3c19a23a6a680343b24f7)。看过但不采用：违反 UPGRADE 的项目文件保护原则，也会丢失 Windows 兼容修正和本项目发布逻辑。官方模板的工作记录清洁检查只适用于模板仓库，不能带入真实项目。

### 2.4 可行性分析

| 维度 | A：官方原文 + 项目适配 | B：整包覆盖 |
| --- | --- | --- |
| 技术匹配 | 保留根目录命令、Windows 支持和索引只读校验 | 路径、换行解析、发版校验有回归风险 |
| 规则冲突 | 显式列出项目例外，原版技能保持原文 | 覆盖项目自有规则及文档，违背官方升级要求 |
| 成本 | 四技能替换，规则合并，状态逐篇核验 | 表面省事，之后需修复被覆盖的项目行为 |

### 2.5 结论与实施建议

结论：**采用现成方案**。按官方 UPGRADE 无版本戳流程升级；原版 skills 保持上游原文，项目差异写在项目规则中。

实施顺序：

1. 记录 Step 0 和迁移计划，保存旧 skills 副本到仓库外备份。使用 `bocode`、`boscope`、`book-writeback`、`bowrite` 原名安装官方四技能到 `.agents/skills/`；移出旧前缀版本，避免重复触发。`.codex/skills` 的空占位文件一并备份后清理，保持一个有效来源。
2. 合并 `book/guidelines/{README,workflow,writing-style,git-workflow,review-checklist}.md`，新增 `task-tiers.md`；更新 `book/{notes,plans,docs,docs/api,docs/architecture,docs/decisions}/README.md` 的适用部分。项目架构、编码规范、历史 ADR 和记录正文保留。上游 ADR 编号不映射为本地同号文件。
3. 在 `AGENTS.md` 明确根目录命令、src 布局、Git log 作为变更记录及官方原文技能的路径适配。M/L 保持完整流程，S 使用新版轻量流程；Always-L 建议覆盖权限、数据迁移、共享 IPC 契约等官方基线领域。
4. 索引采用官方状态解析与分组逻辑，保留本地路径、CRLF、`--check` 和目录用途。逐篇核验：completed 转 done；closed 只有存在已处置证据才转 resolved；monitoring 保留监控说明并归 open；缺状态者按内容与处置记录判定，无已解决证据则 open。只改元数据，不批量宣称问题已解决。
5. 验证索引生成、零警告、内部链接、只读新鲜度检测、无效状态拒绝、CRLF 和 Windows 路径行为；检查 Git diff 没有应用代码变动。运行 `npm run book:release-check`，必要脚本变更跑 lint。
6. 写迁移总结、完成计划、更新必要版权来源说明并写 `.bocode-version`。状态迁移完成且工具同步前不写版本戳。检查旧技能名称引用已清理。此迁移不引入模板仓库专用的 CHANGELOG 发版门禁。

## 3. 风险与开放问题

- 本地 skills 不受 Git 跟踪。此次只升级当前工作区安装；如需让其他工作区自动获得同版技能，应另行决定分发方式，不能把本地安装误报为已随 Git 发布。
- 新技能目录及名称通常要在新会话中重新发现；当前会话已经加载的旧技能清单不会因文件替换自动刷新。
- 上游 README 的部分介绍仍写着 Phase 2 需批准；最新 CHANGELOG、workflow 与 boscope 已说明真实缺口制，实施按实际规范文件处理。
- 保留“changelog 未启用，以 Git log 为准”是本项目既有适配；上游原版 skills 提及 changelog 时需按 AGENTS.md 执行。
