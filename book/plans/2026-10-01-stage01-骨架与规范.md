# Stage 01 项目骨架与规范 — plan

> 批准记录：2026-10-01 用户下令「开启一个新的分支，执行计划」（bocode-boscope：明确下令实现算批准），此前已确认砍除 Notification 与 tailwind。分支 `feature/stage01-skeleton`。

## Requirements brief（Step 0）

**背景**：仓库只有 electron-vite 模板代码。stage 03 起要写真正的 UI，先把骨架、规范、UI 基建立起来，避免后面每个功能各自发明目录形态。

**范围（影响什么）**：

- 安装 UI 基建依赖：styled-components、zustand、lucide-react（均为运行时依赖）
- 订立组件书写规范，落 `book/guidelines/coding-style.md`（现为空模板）
- `src/main/`、`src/preload/` 按业务拆目录；`src/shared/` 契约层目录就位
- 原生对话框通道打通：主进程 `dialog.showMessageBox` 统一承载确认框与反馈提示，不用 Notification（免系统通知权限）
- 模板演示代码（App.tsx、Versions.tsx、模板样式与 svg 资产）替换为骨架自检壳
- 构建配置跟进：electron.vite.config.ts、两个 tsconfig
- 文档同步：`book/docs/architecture/项目骨架.md`

**排除项（明确不影响）**：

- 不写任何业务 UI——会话列表/分栏是 stage 03；主题 tokens 是 stage 02
- 不碰 Android/SDK/scrcpy 任何逻辑（stage 04）
- 不动 electron-builder.yml 打包配置、不动 eslint 规则集
- 不引入 tailwind 与 Notification（2026-10-01 拍板砍掉：样式只用 styled-components，提示统一走原生对话框免通知权限）
- 不做 i18n、不做设置窗（stage 05）
- vitest 测试基建是 stage 01 的 `[suggested]` 步骤，**未获批准前本 plan 不含它**；Phase 4 以手动验证 + typecheck + lint 过关

**需求本身**：完成判据见 stage 01——`npm run dev` 出自检壳界面，typecheck/lint 全绿，规范文档成文。

**learn/ 检索**：现有两篇（perl 就地编辑、skill 命名空间）与本任务无关。

## Design（Phase 2）

### 目录形态（规范核心：目录名 = 业务名，主文件 index.ts）

```
src/main/
├── index.ts              # 瘦入口：app 生命周期 + 装配
├── window/index.ts       # createMainWindow()
├── ipc/index.ts          # registerIpcHandlers()：聚合各域 handler
└── dialog/index.ts       # 原生对话框服务（确认框 + 提示统一）
src/preload/
├── index.ts              # contextBridge 组装 window.api
└── api/dialog.ts         # window.api.dialog
src/shared/               # 三进程单源契约
├── ipc-channels.ts       # 通道名常量（唯一来源）
└── types.ts              # DialogOptions / DialogResult
src/renderer/src/
├── App.tsx               # 骨架自检壳
├── components/           # 业务组件（stage 03 起填）
├── hooks/                # 全局 hooks
└── stores/               # zustand store
```

### 组件书写规范（落 coding-style.md 的要点）

- 组件名大驼峰；`const DeviceList = (props: DeviceListProps) => {...}` + 底部 `export default DeviceList`；props 解构取用
- 组件 ≥600 行拆目录：`components/DeviceList/`（index.tsx 主文件 + 子组件按组件名命名文件 + 私有 hooks 进目录内 `hooks/`）；全局 hooks 进 `renderer/src/hooks/`
- styled-components 只建最外层一个 Wrapper；styled 的动态 prop 用 `$` 前缀（transient，避免透传到 DOM）
- icon 一律 lucide-react，禁 emoji
- 模态框/toast 禁 render 层实现：走 `window.api.dialog` / `window.api.toast`（Electron 原生）

### IPC 数据流

```
对话框：renderer → window.api.dialog.show(options) → invoke('dialog:show')
        → main dialog/index.ts → dialog.showMessageBox(win, options)（异步，不阻塞主进程）
        → DialogResult{ response } 回传
        按钮数区分形态：单按钮 = 提示弹窗（原 toast 的替代），多按钮 = 确认框
```

preload 白名单纪律自本 stage 确立：只暴露 `window.api.{dialog,...}`，移除模板的 `electronAPI`（原始 ipcRenderer）暴露。

### 自检壳（App.tsx，本 stage 的验证载体）

一个最小页面：标题（styled Wrapper）、一枚 lucide 图标、一个 zustand 计数 store、两个对话框按钮——多按钮确认框（校验返回索引）+ 单按钮提示框。四项即 Phase 4 的手动验收清单。

## Build order

1. 依赖接入：装 3 个包，electron.vite.config 加 `@shared` 别名，两个 tsconfig 跟进——验证：`npm run typecheck` 绿
2. 三进程目录拆分：main 瘦入口 + window/，preload 白名单骨架（api 暂空对象），shared 两文件——验证：typecheck 绿 + `npm run dev` 行为同前（窗口能起）
3. dialog 通道：shared 常量与类型 → main dialog 服务 + ipc 聚合 → preload api + d.ts——验证：typecheck 绿
4. 自检壳：App.tsx 重写 + global.css + stores + lucide，删模板资产——验证：dev 起来，四项自检全过
5. 文档：coding-style.md 填实、项目骨架.md 现状节重写——验证：链接走得通、说人话
6. 收尾：stage 01 五步勾选附结果，plan 状态翻 completed
