## Requirements brief

点击「新建设备」后，avdmanager 画像和远端镜像清单需要等待。向导应立即显示窗口与加载反馈，数据返回后显示列表，失败时能重试。

- 作用域：向导画像/镜像清单的首次加载、失败重试和下载后刷新反馈。
- 排除项：Android Studio 分类布局、系统镜像筛选、高级设置、镜像下载取消/排队、SDK 自动引导、主窗全局 loading。后两类新布局另见 [调研报告](../think-report/20261005221831-模拟器向导分类与附加设置.md)。
- 边界：沿用原生模态子 BrowserWindow、三步向导与现有 SDK IPC；实际耗时无法量化为百分比，清单拉取用不定进度动画。

验收要求：等待时显示旋转图标及「正在加载设备画像…」或「正在加载系统镜像…」；加载中不显示「清单为空」；加载成功且结果为空时才显示空态；失败显示中文错误与对应清单的重试入口；取消/关闭始终可用。

## Impact range

[DeviceWizard.tsx](../../src/renderer/src/components/DeviceWizard.tsx) 的首载同时 `Promise.all` 画像与镜像；没有首载状态，两个结果全部完成才更新列表。`reloading` 仅供镜像刷新，错误区的「重试」也只调用 `loadImages`，画像失败无法重拉。

[wizard.ts](../../src/main/window/wizard.ts) 已在 `ready-to-show` 后展示窗口；[SDK 域](../../src/main/emulator/index.ts) 已有画像 5min、镜像 60s 缓存。动画在 renderer 表达等待，不改变缓存或 IPC。

| 文件                                                          | 动作                                                         |
| ------------------------------------------------------------- | ------------------------------------------------------------ |
| `src/renderer/src/components/DeviceWizard.tsx`                | 拆开两个资源的加载状态；增加加载/空/错误反馈；按失败资源重试 |
| `src/renderer/src/components/__tests__/DeviceWizard.test.tsx` | 用可控 Promise 覆盖慢请求、部分失败、重试和卸载              |

风险：一个慢请求拖住另一个列表；旧请求覆盖重试结果；卸载后迟到回调更新状态；用清单刷新动画替代既有下载百分比。

## Design

每份资源持有 `idle/loading/ready/error`、数据和错误。图片下载继续持有原有包名/百分比状态，不能与清单 loading 合并。

1. 首次挂载无注入数据时，两份请求并发发起，分别接住成功与失败，各自更新。`data` 注入的测试场景直接视为 ready，即使数组为空也不显示 loading。
2. 第一步只受画像状态控制。画像到达后即可选设备并进入第二步；镜像仍慢时第二步显示它的加载态，不必等待画像页上的网络请求全部结束。
3. 列表首载为空时，在列表区域居中显示 lucide 旋转图标、中文状态文字，区域标记 `aria-busy`，文字使用 status 语义。亮暗样式沿用 tokens；减少动画偏好下保留文字。
4. 每个加载函数统一用于首载与重试；画像错误重试画像，镜像错误重试镜像。失败结束 loading，不进入成功空态，不弹重复原生错误框。
5. 有数据的刷新保留已有列表，在列表顶部显示紧凑加载反馈；与刷新相关的推进/创建操作等新结果确认后再允许。成功后按 id/packageName 核验选择仍存在；不存在则清选择并禁用推进。
6. 请求使用组件存活标记和每资源请求代次；只接纳当前代次。关闭、取消或新请求发起后，旧结果不改变界面。此处忽略迟到响应，不宣称已经取消 main 的 Java/网络任务。
7. 下一步/创建由当前步骤所需资源 ready、选择有效及现有防连击守卫共同决定；页脚和取消入口不随列表状态移动。实施时使用 impeccable 技能检查等待反馈。

无新共享类型与 IPC。后续向导布局重做时复用这套资源状态，不重复实现首载逻辑。

## Build order

1. 拆出每资源的加载、错误及请求代次，保留数据注入。验证：画像先完成可展示，镜像慢不拖住第一步。
2. 接入不定进度动画、空态与独立重试。验证：慢请求/空结果/SDK 未就绪/网络失败分别有正确反馈。
3. 接入下载后刷新和选择核验，验证百分比与刷新状态连续，创建防连击和下载完成前禁创建仍成立。
4. 相关向导测试、typecheck、lint、改动文件格式检查；实际 Electron 首次打开与重试冒烟。Phase 5 只记录 review 发现，Phase 6 同步 book。

## Test plan

- 画像、镜像均未 resolve：第一页有加载动画/文字，下一步禁用，取消可用。
- 画像先成功、镜像仍 pending：画像可选、可进入镜像页，镜像页继续 loading。
- 仅画像失败 / 仅镜像失败：对应错误可见，重试调用正确资源，另一份成功数据保留。
- 空数组成功、缓存快速命中、注入空数组：分别进入空态或列表，不残留 loading。
- 慢旧请求与新重试交错、卸载后 resolve：旧结果不覆盖当前结果，不产生未处理拒绝。
- 下载中保留百分比与互斥；下载后重拉显示刷新反馈；失败可重试，未安装镜像不能创建。

复用既有三步选择、命名、创建与取消回归。真实窗口人工核验首载/失败/重试的动画与亮暗样式；不人为清理用户 SDK 缓存或卸载镜像来制造慢请求。
