# 配置差异的采用与同步

## Step 0 需求

用户希望警告旁有一个简短按钮，用 config.ini 的值更新对应表单；不点击则保存时按当前表单写回不一致项，即使输入框没有改动。按钮文案采用“采用配置值”，它表示文件中的配置，不宣称安卓实时运行值。

范围：已有可编辑字段的配置偏差、逐项采用、默认保存同步、容量单位等价比较、字段校验、并发与事务回归。沿用现有编辑页样式与按钮。

排除：内部存储/ABI/机型/API、数据盘、批量修复、已有 legacy 未知值的编辑开放、Quick 开放、之前延期的五项验收、提交/推送。警告中的只读项继续只读。

## Phase 1 分析

现有 buildEditDraft 仅按字符串比较并输出警告；DeviceEditor 只提交与元数据不同的字段；main 也只把元数据变化转成 patch。因此“表单未变但 config 不同”永远不会写回。vm.heapSize=228M 的单位还会使等值数字 228 被误判。

影响：shared 类型与编辑归一化 → main 语义差异检测/强制差异映射与保存 → renderer 逐项采用与保存可用态。风险：把所有旧值都重写、未知值被默认值替换、采用相机或皮肤绕过资源验证、外部文件变动被覆盖。

## Phase 2 设计

- 新增只读结构化 configMismatches：字段、文件值说明、可识别的 typed actualSettings；无法识别时 actualSettings=null，不能采用。仅已有可写配置映射参与，内部存储不进入该集合。
- 纯模块 configDrift.ts 语义读取 CPU、RAM、heap、GPU、相机和已配置的朝向/皮肤。数字 MiB 与 M/G 后缀归一；语义相同不告警。缺失键沿用现有默认/继承语义，不擅自新增冲突。皮肤采用仅允许已枚举可识别引用。
- 每个差异行旁“采用配置值”；点击只改对应草稿，不立即写文件，不覆盖其他草稿。采用后显示“已采用，保存后同步应用记录”。无法识别的值解释原因，不显示采用按钮。
- 存在偏差即允许保存；所有偏差字段都进入显式同步集合。main 从当前受控 config 重新计算集合，不信任 renderer 提供的路径/配置键。未点击时用表单值；点击后按表单采用值。支持一部分采用、一部分覆盖。
- normalizeEditedSettings 增加待同步字段参数，使未变更但将写回的字段仍执行能力/资源及 RAM/heap 联动校验；无偏差字段继续保留旧语义。相机同步复验与预留。
- patch 以可识别实际 config 为基线；采用时保留已有文件写法（例如 228M），只同步元数据。未知实际值由显式同步强制写回白名单。真实变更仍走现有指纹/健康/互斥/journal/CAS/广播，快照按配置变化失效。
- 文件清单：shared/types.ts、settings-contract.ts、main/emulator/configDrift.ts、deviceConfig.ts、devices/index.ts、renderer/components/DeviceEditor.tsx 与相邻测试。无新增 IPC 通道或依赖。

用户本条指令已明确两种行为，作为实现授权；无需再次确认。

## Phase 3 实现

已完成结构化偏差读取、逐项采用、未改输入的保存同步，以及 main 端重算和校验。存储/ABI 不进入同步集合；采用数字配置时保留 228M 等原始写法。保存失败保留已采用值和其他草稿。无偏差的旧字段仍按差异保存。

## Phase 4 测试要求

等单位无假冲突；228M 真冲突、未知数值/重复键、相机/皮肤解析；不改表单保存仍覆盖；采用后元数据同步且文件原文保持；混合选择；存储/ABI 不进入载荷；能力/联动与相机预留不能绕过；运行态/外部改文件仍阻断；renderer 按钮、可用态、失败保留草稿。相关与全量测试、typecheck/lint/build；窄窗/亮暗视觉检查。

验证结果：

- 全量 671 项通过、6 项跳过，47 个测试文件通过、3 个跳过，无未处理异常；本轮净增 25 项，涵盖采用、默认同步、混合选择、等价单位、未知值、外部冲突和失效相机复验。
- npm run build（包含 node/web typecheck）、npm run lint、npx prettier --check src、git diff --check 通过。
- 使用实际 DeviceEditor 的临时浏览器预览检查亮/暗主题及 480/720 像素宽度；较窄显示下提示与按钮可换行。点击 VM heap 的采用按钮后输入为 228，RAM 保持 2048，提示改为“已采用”。临时页面与服务已清理，未写用户 AVD。Electron 编辑窗最小宽度仍为 860，未改窗口策略。
- Impeccable 检测无新增问题，仅报告既有标题 14px 不在 DESIGN.md 字号表内的 advisory；本轮新增按钮沿用 11px 和既有 Button。
