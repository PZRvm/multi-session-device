## Design

### B1：画像枚举使用当前 SDK 的 JRE

1. 为 `listDeviceProfiles` 显式传入 `sdkRoot`，在默认执行器中按当前托管 SDK 规则构造环境：`JAVA_HOME=<sdkRoot>/jre/Contents/Home`，SDK 与用户目录变量沿用现有 AVD 工具执行的隔离口径。宿主 `JAVA_HOME` 不能覆盖应用选择。
2. 更新 `profilesCached`、创建事务重新核验、`buildEditCapabilities` 三处调用；保持画像缓存键、创建时重新查询及编辑能力降级的既有行为。
3. 自带 Java 缺失或无法执行时给出 SDK/JRE 修复提示，保留失败原因；不静默依赖宿主 Java，不把执行失败当空画像列表。
4. 只调整画像执行环境，不借此重构 bootstrap、SDK 来源或所有子进程执行器。

验收：清除测试进程的宿主 `JAVA_HOME`、设置不含可用 Java 的 PATH 后，默认执行器仍使用自带 Java，向导画像与能力查询成功；SDK 根含空格可用；宿主 Java 指向错误目录时不受影响；JRE 缺失时能明确报错。真实验证使用单独的测试启动环境，不修改用户全局环境。

### B2：窗口加载失败后释放单例并提示

1. 把一次打开的窗口、上下文、加载状态和清理函数绑定在同一代次；创建前同步保留互斥，构造异常也能解除标记。
2. 捕获 `loadURL/loadFile` 的 rejection，处理主 frame 的 `did-fail-load`、就绪前渲染进程退出，以及 15 秒内未 ready 的加载超时。失败出口共用幂等清理，取消计时器并销毁当前隐藏窗口。
3. 清理全局引用前核对窗口身份。旧窗口迟到的 ready、closed 或 rejection 不得复位新窗口、显示已销毁窗口或覆盖新上下文。
4. 打开 IPC 等待本次窗口 ready 或失败；失败交给 App 已有“打开向导失败 / 打开编辑窗口失败”提示。并发同上下文打开共用本次结果，不同上下文保留原冲突提示；用户主动关闭与主窗关闭按取消收口，不当加载故障弹错。
5. 成功后保留重复打开聚焦、创建/编辑上下文隔离，以及原 sender 权限检查。

验收：加载拒绝、主 frame 失败、超时各有一次错误提示；失败后再次点击能打开。重复失败事件不重复提示，连续打开只生成一扇窗口；旧代次事件不影响新窗口。受控 BrowserWindow 测试之外，使用隔离 Electron 窗口模拟错误 URL，验证“失败提示 → 重试成功”。

### B3：布局可用后开放画布操作

1. 在布局 effect 中先读取容器初始尺寸，再注册 ResizeObserver 更新后续变化。初次测量与观察回调采用相同的容器内容区域口径，避免 padding/border 造成首帧偏移。
2. 保留流连接状态，另派生视图就绪条件：流 ready、format 有效、layout 有效且屏幕尺寸大于 0。无需新增 main IPC 状态。
3. 流已连但布局为空时展示“正在准备画面”；触控和依赖画布坐标的输入按视图就绪条件启用。零尺寸、隐藏窗口保留等待，恢复可见后自动更新；暂停期间不排队补发输入。
4. 保留皮肤、横竖屏、旋转暂停、设备切换与旧代次输入保护，不用任意延时掩盖竞态。

验收：ResizeObserver 首次回调延迟时，正常可见容器仍得到首帧尺寸；容器为 0 或 format 未到时有等待提示、无输入；尺寸恢复后自动显示和响应。真实窗口检查启动、缩放、切换设备及隐藏后恢复，确认画面与触控坐标一致。

### B4：解码前限制皮肤像素数

1. 主进程增加共用元数据检查器，读取图片头部获取宽高，不调用完整位图解码作为预检。覆盖当前支持的 PNG/JPEG/WebP；对截断、零尺寸、非法长度、超出安全整数的预算及无法可靠估算的变体明确拒绝。
2. 设计初值：单边不超过 8192 像素，单图不超过 16,777,216 像素，整套唯一素材不超过 67,108,864 像素。RGBA 估算分别为 64 MiB 和 256 MiB；这些是预算初值，不是浏览器实际内存峰值。实施前统计已有 fixture、本机已下载素材及可获得的官方资源尺寸，记录覆盖范围；正常支持素材超过初值时先调整设计再实现。
3. 同一文件多方向复用只计一次；单图合规但整套超限仍拒绝。保留已有字节、文件数、路径和溯源核验，不以像素预算替代这些限制。
4. 本地导入和官方下载在最终入库前检查，失败清理 staging；presentation 读取再次检查实际字节，保护既有皮肤及外部替换后的文件。失败时返回素材名、尺寸和限制说明，不向 renderer 发送该套图片 data URL。
5. 建议支持静态素材；对动画格式须先识别帧信息并确定预算，不能只检查第一帧后放行。实现不得偷偷扩大当前支持格式；若需要新依赖，先在本计划记录必要性与边界。

验收：三种正常格式和透明遮罩仍可用；小字节大尺寸素材在解码前被拒绝；边界恰好通过、超过一像素拒绝；总量超限、重复引用、损坏头部、既有皮肤被外部换大均有回归。失败不新增半成品库记录，普通官方皮肤仍显示、旋转和透传输入正常。

### B5：先确认回包故障，再修传输或解析

本批次的实现方案有诊断关卡，不能预先断定是 ADB forward 问题。

2026-10-09 实施诊断：隔离 API 32 临时 AVD、钉死 server 3.3.3，经原生产传输收到 57 个控制字节，独立按协议读取到序列号 1 的 ACK；原生产粘贴仍等满 2002ms。手写 reader 把 64 位 ACK 当 32 位、把剪贴板长度从偏移 2 读取而不是偏移 1，且没有接入库 serializer 所等待的 ACK resolver。当前根因落在解析；传输不更换。最终方案：有界控制流交给已安装库的 `deviceMessageParsers`，主动消费 clipboard stream，writer 的 ACK Promise 与既有超时/会话取消共同收口；补分片、粘包、长度和清理回归，再按原场景复验。

1. 在临时 AVD 上复现当前生产链路，分别记录控制 socket 原始收包字节数、消息类型、序列号和解析结果，确认当前版本仍能复现。诊断不记录剪贴板内容，不同步或覆盖宿主剪贴板。
2. 核对钉死的 scrcpy-server 3.3.3 与已安装 `@yume-chan/scrcpy` 的协议实现。重点检查当前手写 reader 的 ACK 序列号宽度、剪贴板长度字段偏移、分片/粘包、reader 注册时机及 socket 读取状态，区分“没有原始字节”和“有字节但解析失败”。
3. 有原始字节时先修解析；优先复用已安装库的设备消息解析能力，避免重复维护协议。若原始读方向仍静默，对照官方客户端握手与同 SDK/设备环境，再用 ADB server 直连 localabstract 做单变量诊断；只有对照证明现有传输有缺陷且替代路径不影响视频时才更换传输。
4. 确认根因后，在本节补证据、文件范围和最终方案，再进实现。若当前无法复现，交付诊断结果及继续捕获条件，B5 保持未完成；不能用 mock 通过关闭真实故障。
5. ACK 以正确序列号匹配当前会话，只表示协议确认。待等待项在超时、断开、停止和切换时收口；对控制消息长度与缓冲设置上限。保留当前超时“已派发”的缓解，不把缺 ACK 当被测控件已成功粘贴；自动同步消息本批只正确消费，不写宿主剪贴板。

验收：真实设备连续 10 次 SET_CLIPBOARD 收到对应 ACK，UTF-8 内容测试可用；自动同步回包可解析；两会话不串 ACK。覆盖分片、粘包、错误类型、超长消息、迟到/未知 ACK、超时与断开；视频、键盘、旋转不回归，结束后只清理本次 forward。诊断临时日志和进程均按所有权清理。

## Build order

1. **B1**：先写默认执行环境的失败回归，再补环境与三处调用；通过隔离 Java 环境验证。
2. **B2**：先复现隐藏窗口加载失败，补单例生命周期与错误返回；验证失败后重开及旧事件隔离。
3. **B3**：用延迟尺寸回调复现状态差，补同步初测与视图就绪条件；验证真实窗口和输入。
4. **B4**：记录正常素材尺寸与预算依据，补头部解析及三条入口；验证拒绝超限与入库清理。
5. **B5**：先做真实链路诊断、落下根因和设计，再红绿回归与隔离设备复验。

每批可独立交付；B1–B4 不等待 B5 调查。每批走分析 → 设计 → 实现 → 测试 → review → 收尾；review 与收尾发现的范围外问题只记录。B5 未完成时只能将前四批标为完成，整份计划继续保持 in_progress。

## Test plan

- 先补能在旧实现失败的回归；测试错误行为和可观察结果，保留既有权限与事务断言。
- 每批运行相关测试；五批源码完成后运行 `npm run test`、`npm run lint`、`npm run build`（含 typecheck）和改动文件的 Prettier 检查。前批的完整检查结果在后续改动后失效，最终再跑一次总门禁。
- 常规测试全绿不替代上述真实环境验收。当前项目的实机测试有硬编码 AVD，不能直接开启 `MSD_SMOKE_STREAM` 复用用户设备；为本计划准备隔离临时设备入口。
