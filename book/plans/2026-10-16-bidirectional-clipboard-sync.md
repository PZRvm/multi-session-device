# 双向剪贴板同步 — plan

依据：[已确认调研](../notes/think-report/20261016125001-双向剪贴板同步.md)、[stage05](../notes/summary/2026-10/2026-10-16-功能完善.md) APK/剪贴板组合步骤、[工作流](../guidelines/workflow.md)。

2026-10-16 用户确认调研方案，并要求执行 workflow 前三条、编写计划。先完成 **Step 0、Phase 1、Phase 2**；用户后续下令在本工作区实施并确认人工验收通过，review 发现的 P2/P3 亦获批修复并复审关闭，现已 completed。历史实施与审查记录保留如下。

## Requirements brief — Step 0

### 背景与目标

当前电脑文本能通过画布粘贴到设备，但设备复制消息在 main 中被丢弃。目标是当前设备复制后电脑可直接粘贴；电脑复制后，设备内长按粘贴也能用新文本，不再依赖先按一次电脑粘贴快捷键。

### 已确认需求

1. 仅同步右侧当前选中的设备，不向所有运行设备广播。
2. 纯文本，保留中文、英文、换行、空格和表情原文；不 trim。
3. 首次连接不处理两端旧内容，只建立变化检测基线。
4. 空字符串、没有文本格式时不清空另一端；图片和文件不在本批。
5. 同一实现覆盖模拟器与 USB/无线真机。
6. 电脑端单一定时器，每 300ms 检查一次；设备端复用 scrcpy 事件推送。无目标、未 ready 或断开时停止宿主检测；变化才发送。
7. 性能影响通过实现后的 CPU、内存、投屏实测判断，不预先承诺零影响。

### 范围与边界

- **影响：** main/scrcpy 剪贴板读写、active/session 生命周期、必要的输入来源标识与相关回归；错误词条沿现有三语机制维护。
- **不影响：** SDK/AVD 配置与持久化、无线连接和扫描、设备创建/删除、视频缓存/解码/恢复算法、截图保存、APK 安装、日志、网络开关。不得借本任务修复已登记的初次建流失败重试问题。
- **不做：** 图片/文件传输、剪贴板历史、跨设备广播、系统全局快捷键监听、原生扩展、远端服务、自动恢复旧剪贴板、新设置页或工具条开关。
- 不引入依赖，不升级 Electron/Tango/server。宿主剪贴板正文不发 renderer、不落日志和磁盘。
- 前轮仅产出计划；实施已在当前工作树建立 `codex/clipboard-sync` 分支，保留既有文档改动。本批不自动提交或合并。

## Design — Phase 2

### 1. 数据流与归属

```text
电脑剪贴板 → 主进程 300ms 采样 → 变化/格式/大小检查
           → 当前绑定与 revision 检查 → per-session 写队列
           → setClipboard(paste=false) → 当前设备剪贴板

设备复制 → 已有 scrcpy clipboard 流 → 当前会话/绑定检查
         → 检查宿主未采样变化、过滤回声 → clipboard.writeText
         → 同步更新宿主采样基线（下一轮不回传）

主动粘贴/IME → 既有 screenInput 守卫 → 同一写队列
            → setClipboard(paste=true)，仅写设备并触发一次粘贴
```

同步归属采用 active，不采用窗口焦点：用户切到电脑文本编辑器后，当前设备仍是同步目标。没有 active 时不读宿主；选中的会话 ready 后才建立基线并启动检查。

切换、首次连接、重连均采用保守策略：读取宿主当前状态作为基线，不写任一端、不回放后台设备旧内容。切换同一设备的新 viewToken 也换绑定 epoch。此为对“首次连接不处理旧内容”的一致延伸，不增加覆盖行为；新复制后恢复同步。旋转/视频重同步只改视频 generation 时，不重建剪贴板基线；剪贴板不依赖视频帧流畅与否。

### 2. 协调器与内部接口

新增 `src/main/scrcpy/clipboardSync.ts`，职责限定为同步状态机；不导入 ipc、媒体恢复或 lifecycle。通过回调查询当前绑定、发送文本、报告错误，避免下层反向依赖上层。

内部契约（名称可随现有类型规范调整，语义固定）：

| 接口                                                          | 语义                                                                      |
| ------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `rebind(target \| null)`                                      | 撤销旧 epoch、清 pending、停计时器；有效 ready 目标采基线后开启唯一计时器 |
| `acceptDeviceText(target, content)`                           | 非阻塞处理设备文本；不接受后台、旧会话、空串或自身回声                    |
| `observeLocalWrite(target, content, source)`                  | 标记本程序发给设备的文本及来源，供回声过滤与并发协调                      |
| `dispose()`                                                   | 幂等撤销任务/定时器/错误去重状态，允许管理器后续重新绑定                  |
| 注入 `readSnapshot/writeText/setTimer/clearTimer/reportError` | 测试不碰真实宿主剪贴板，生产用 Electron API；时间接缝遵循已有测试习惯     |

target 至少包含 deviceId、runId、streamId、viewToken 和 session 身份引用；epoch 属协调器，每次 rebind 增加。同步 revision 每次接受新复制事件增加；旧 pending 不能在新 revision 后发送。每次 await 之后再校验，不只在入口校验。

宿主 snapshot 包含格式集合与可用文本；无纯文本、空串也更新观察基线，但不向设备写清空。基线不能只记录最后一个非空值，否则 A→图片→A 会被错误去重。空格/换行是有效内容。

### 3. 事件顺序、防循环与并发

- 每次 tick 同步读取快照，与观察基线比较；无变化直接返回。新非空文本创建宿主来源 revision，更新 pending，仅对当前目标发送。
- 设备消息进入时先采一次宿主：若发现自上次基线之后存在宿主变化，优先处理该变化，丢弃本条竞争设备消息；否则处理设备新文本。这一顺序保证未采样的电脑复制不会被立即覆盖，但不保证物理时间上的最后复制者胜出。
- 写宿主前再次检查目标有效性。相同纯文本可免重复写入，避免破坏宿主已有富文本/图片格式；正文不同才 writeText，并立即更新基线与 revision。
- 每个会话记录自身最近已发文本及来源，回声记录有界：最多 16 条、每条 2 秒有效，完成/过期及时清理。匹配到自身文本的设备回声不写宿主；相同文本被用户再次复制但没有可靠来源信息时，允许被该短窗口去重，不能宣称捕获每一次复制事件。实测若表明厂商延迟超出窗口，回到设计调整，不能无限缓存正文。
- 已丢弃的后台消息不缓存、不在切回来时重放。消息协议没有用户复制时间戳；归属按接收与处理时可验证的绑定判断，无法证明延迟包在设备端的实际生成时刻。硬件验收需覆盖快速切换，不把检查 epoch 当成消除所有跨端延迟的证明。

### 4. 写队列、主动输入与 ACK

扩展 `ScreenInput` text 分支，可选 `source: 'paste' | 'composition'`，仅用于 ime=true 的来源区分；缺省按既有内部输入处理，不授予额外能力。运行时守卫拒绝非法枚举及与 ime=false 矛盾组合。preload 仍透传既有 typed screenInput，不新增 IPC；同步检查其声明是否直接引用共享类型。

renderer 仅在 onPaste 与 onCompositionEnd 添加 source；普通键入、焦点、旋转暂停及隐藏 input 行为保持。

每会话一个剪贴板队列：实际 writer 调用单飞，显式输入 FIFO（最多 16 个等待任务，超限明确拒绝）；自动同步只有一个最新 pending。当前任务完成后优先处理显式输入，再发送最新同步。队列任务执行前检查原始信封绑定，切走直接取消未发任务，不补发旧输入。

自动同步使用 `paste: false`，显式输入仍 `paste: true`。IME 只更新设备并粘贴，不把组合文本写回宿主；不为恢复设备旧剪贴板引入额外读写。当前输入法借剪贴板的副作用保留，后续新的用户复制仍可同步。

公共写入层复用 sequence、安全 writer 与原有 ACK 上限；超时分两层：外部主动输入保留现有 2s 降级语义，但底层 writer 未 settle 前不解除队列单飞；实际 writer 5s 仍未 settle 时按控制通道故障销毁本会话，取消该会话 pending，保证不会无限等待或积压 resolver。晚到 resolve/reject 仍接住且不能恢复旧绑定。具体超时常量独立于视频恢复计时器。

同步任务可合并，用户主动粘贴不可被合并或丢成成功；被取消、队列满或写失败均有明确 Promise 结果。整个 queue 不等待来自 clipboard 消费循环的操作，避免循环依赖死锁。

### 5. 预算和错误反馈

- 自动同步正文上限 `262130` UTF-8 字节，按较小方向协议预算收敛；超限不发送、不截断、不分片（分片会把剪贴板变成最后一段）。
- 现有 screenInput 主动文本 4KiB 限制不扩大。自动同步不借 renderer input 通道，因此可支持更大文本；“已同步的大文本”不代表旧主动粘贴 API 的限制已解除。
- 设备→电脑已可能被 server 截至 `262139` 字节，本批接收超过 `262130` 时跳过并提示；小于等于上限也不能保证原文从未被服务端截断，此限制写入验收记录。
- 读取失败或 writeText 抛错，不修改成功基线、不关闭解析流；每个绑定、每类错误最多提示一次，后续 tick 可重试。设置合理读失败退避（连续失败后间隔 3s，成功恢复 300ms），防止故障日志/弹窗风暴。
- 用主进程现有 Electron 原生 messageBox 方式提示同步失败/超限，无新 UI；经依赖回调装配并接住拒绝，词条进 `src/shared/i18n/errors.ts` 三语字典。提示包含错误类别与设备标识（scrcpy 层没有显示名查询接口），不含正文；切换后的旧错误不弹。
- 底层控制通道写失败继续既有 screen error/清理行为，不另加重复弹窗。ACK 只表示协议确认，不显示“目标输入框已接收”的虚假成功。

4. **main 接线：** clipboard 流接协调器；active 更新、ready、清理和 preserveActive 重建分别接线；补错误词条与原生错误反馈，验证 parser 不等出站 ACK。

### 硬件与性能

1. 模拟器里复制新字符串到电脑外部编辑器；电脑复制后在设备长按粘贴；中英/换行/表情往返，确认自动同步不会自动输入。
