## Phase 1：影响与风险

- renderer：App 稳定持有录制订阅；新共用状态组件用于两类设备行与计时，替代 RecordingTasks；命令失败仍有可见反馈。
- main：录屏确认扩展为可携带记忆上下文；原生结果由独立队列负责，不阻塞媒体生成。窗口关闭、结果重试、真正退出需避免重复或丢失提示。
- 偏好：独立版本文件，main 内存镜像与串行原子落盘；取消/过期答复不保存。恢复与在途确认通过代次隔离，不能恢复后又被旧弹窗写回。
- 权限：新增恢复通道只允许登记设置窗的主 frame；不得开放给处理页或任意主窗载荷。

## Phase 2：设计

1. `main/recording/preferences.ts`：载入、匹配、接受记忆、统一清除；偏好键由 main 的 AVD id / 可验证物理身份 / 未知实体的 transport 身份以及归一尺寸或稳定音频原因类别组成。无法稳定分类的临时错误仍询问，不把错误全文当永久键。每次仍探测音频，正常时录音。
2. manager 的 confirm 增加可选上下文（记忆键与当前任务检查），返回仍为 boolean；提示服务在有效肯定答复且勾选时才落盘。清除递增代次，拒绝旧在途确认写回；resize/discard 不免提示。
3. `main/recording/notifications.ts`：按 taskId/终态排队，saved 与 error 才通知，queued/processing 重置重试通知代次。成功提供定位/关闭；失败提供重试/稍后，保留材料。主窗未可见或关闭时保留待提示，重开通过已授权主窗快照请求唤醒；原生弹窗以可见主窗为 owner。退出流程暂停通知，取消退出时恢复。结果不自动播放。
4. `recording:reset-prompts` / preload `resetPrompts():Promise<void>`：设置主 frame 专用。恢复只清两类偏好，不触碰任务/媒体。通用设置显示按钮、忙态和完成/错误反馈，三语。
5. App 订阅快照并显示全局命令错误；`.canvas-tools` 同一 flex 组对齐当前设备计时与 Logcat，间距 12px。选中任务优先级为活动、生成、可处理错误；暂停冻结，非录制设备不显示后台计时，生成可显示进度，失败提供重试入口，便于稍后处理。
6. 新 `RecordingStatus.tsx` / `RecordingIndicator.tsx` 共用三语和快照；列表只显示状态，不显示用时。旧顶部任务组件移除。成功关闭移除成功展示状态但不删视频，失败稍后不清理材料。
