# Windows 顶部窄窗修复轮次

## Step 0：需求简报

- 背景：主计划首轮实现已通过定向测试，独立评审及真实窗口测量发现 Logcat 在 500px 主窗、420px 左栏时越过原生按钮安全区。
- 范围：App 顶部两个 flex 子区的空间分配，以及窄窗几何回归验证。
- 排除：不改设备列表宽度、主窗最小宽度、dock 宽度规则、业务处理函数、macOS/Linux 或原生按钮配置。
- 需求：原生安全区不足以放下完整左侧板头时，顶部左区按可用宽度收缩，为 Logcat 保留 30px 按钮及 10px 间距。日志按钮始终位于安全区内。
- 授权依据：用户已批准执行主计划，其验收明确要求标题和按钮不遮挡；本轮修复同一验收范围，没有新增产品行为。

## 阶段 1：分析

`App.tsx` 的 `.windows-board-head` 为 `flex: none`，按 listWidth 固定占位；`.header-actions` 最少还需 40px。当前安全区 364px，左区却固定 420px，导致日志按钮落在 420–450px。

## 阶段 2：设计

- 左区改为 `flex: 0 1 auto; min-width: 0`，保留正常宽度，空间不足时允许收缩。
- 右区改为 `flex: 1 0 40px; min-width: 40px`，日志按钮与右侧间距不参与收缩。
- 原来的按钮安全区环境变量、顶部高度、菜单溢出和标题省略继续生效；不通过 clipping 隐藏溢出，也不增加主窗最小宽度。
- 相关 App.logcat 测试在并行复验中暴露既有异步时序：DOM 卸载先于 dock 解锁 effect。解锁断言改用 waitFor 等待同一预期，不弱化断言。
- 验证先运行已复现的真实窗口失败断言，再修改样式；修复后检查 500px/420px 组合、正常窗口和三个缩放档。
