# 本地与 GitHub 提交历史对齐

## Step 0：需求简报

- 背景：首次公开发布用了独立快照，远端只有一个提交，本地 dev 有 405 个提交。
- 需求：用户要求本地和远程提交对应，已明确允许 book 及其历史一并公开，取代原先排除 book 的发布要求。
- 范围：提交当前工作树，配置本仓库 origin，连接本地和远端 dev 的历史，上传完整 dev 历史并验证两端一致。
- 排除：不重写原提交、不强推、不推 main 或无关工作分支、不修范围外功能、不删除先前发布目录。
- 验收：原 dev 的全部 405 个提交以原 ID 成为远端 dev 的祖先；book 和 LICENSE 已跟踪；本地和远端 dev 的 HEAD、提交数、文件树一致；工作树干净。

## 阶段 1：分析

本地 dev 起点为 3d6f32b，远端 dev 为独立根提交 5748ed8。本地未提交内容包括此前已发布的源码修复、MIT 声明和内部记录，用户已授权一并上传。此前已对原 dev 的 2858 个历史 blob 扫描明显凭据模式，未发现命中；没有疑似凭据文件或大于 50 MiB 的历史 blob。

## 阶段 2：设计

先保存当前工作树为普通提交；核对远端仍为 5748ed8，确认公开快照中的源码都已在本地工作树。使用保留本地树的无关历史合并连接远端快照，不移除任一已有提交。公开快照 AGENTS.md 的差异按本次要求恢复为适用于完整 book 的本地版本。

origin 使用 HTTPS 读取、本机既有 SSH 身份推送。推送只指定 dev，用普通快进更新。维护本地备份引用，不通过任何过滤器重写提交。

CI 的提交主题检查排除原 dev 基线 `3d6f32b8bbc4c6572173f0d01abdaec75237f74b` 的祖先集合，落实“旧历史不重写”的既有规则；仍逐项检查基线之后引入的新提交。否则本次迁入会把旧历史全部当新提交检查，迫使修改原 ID。只调整范围选择，不改变校验器规则。
