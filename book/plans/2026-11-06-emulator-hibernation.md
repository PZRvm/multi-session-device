## Tier 与 Step 0 — Requirements brief

**L。** 涉及 VM 状态持久化、设备生命周期与共享 IPC 契约，不能按小改处理。实施后的首个提交正文记录分级、动机与验证方式。

### Background

闲置模拟器仍占 CPU、GPU 和内存；普通停止后重新冷启动会丢失当前桌面/应用现场。用户选择的是释放内存的休眠，允许恢复稍慢，期待回来后继续原来的操作。另需移除运行时的删除入口，避免误删。

### Scope

- Affects：官方快照适配、设备生命周期及恢复清单、主进程互斥与资源回收、共享类型/IPC/preload、列表动作与画面占位、用户删除状态守卫、相关三语文案与测试。
- Does NOT affect：USB/Wi-Fi 手机、自动闲置计时、批量休眠、通用快照管理器、普通停止语义、默认 GPU 设置、SDK/镜像下载、安装包发布流程、范围外问题及视觉重构。
- Boundaries：一次操作一台自有 AVD；状态以主进程为准；休眠仅在快照确认保存且所属进程退出后成立。恢复必须证明加载了保存状态，不能冷启动后报“恢复成功”。
- Platform：Mac 先验证；Windows 独立通过相同门槛后开放。未经验证的平台/后端不展示可执行的休眠入口，并说明原因，不把 Mac 结果外推。

### Requirement

1. 运行设备手动休眠，释放实例进程及媒体/连接资源，保留可恢复的桌面与应用状态。
2. 应用重启后仍识别休眠记录；用户手动恢复，获得新 runId、有效投屏与输入链路。
3. 已休眠时只有“恢复”和明确的“放弃休眠状态”路径；放弃需确认，回到 stopped 后才能冷启动或删除。
4. 用户删除按钮仅 stopped 渲染；运行态和过渡态均没有可聚焦的删除入口。主进程用户删除也拒绝非 stopped，保留确认和原有写保护/来源桶限制。
5. 内部已经授权的 SDK 清理仍可停止并级联删除设备，不受用户按钮策略误伤。
6. 失败保留真实状态、错误原因及恢复选择；不静默丢弃休眠快照，不声称保存现场等同于远端连接/调试器无感续接。

### 主要风险

- 快照原生稳定性与软件 GPU 兼容性；已有 Quick 门槛未通过。
- 保存、进程退出和清单提交不是单个原子动作，崩溃中间态必须可解释。
- 恢复加载磁盘/内存快照具有回滚语义，误复用旧快照会回滚后续工作。
- 保存时仍有输入、录制、安装或截图落盘会破坏现场一致性；仅加 UI disabled 无效。
- 旧 scrcpy、剪贴板、日志或图片窗口凭据随快照恢复会混入新运行代次。
- 休眠释放进程内存但增加磁盘与保存/加载 IO；不承诺宿主总内存立即下降固定比例。

## Phase 2 — Design

### A. 原生能力门槛先行

不以历史“快照目录存在/mtime 较新”替代可恢复性证据。新建可丢弃 AVD，使用独立 ANDROID_AVD_HOME/ANDROID_USER_HOME、空闲端口和本轮拥有的进程；不对用户实例执行 save/load/kill。

1. 完成 host 后端单机十轮、双机各五轮保存→退出→恢复。
2. 每轮核验内核 boot_id 相同、前台应用/页面状态保留、ADB 就绪、截图与实际投屏/输入可用；两台身份不能交叉。
3. 记录冷启动、保存、退出、加载以及恢复到可操作画面的分段耗时、QEMU RSS、CPU、宿主可用内存、快照实际磁盘分配。
4. 验证低磁盘、保存失败、异常退出、取消、缺失/损坏快照及 GPU/镜像/工具/配置变化；确认无静默冷启动。
5. 验证 Windows 并记录独立证据；无法实测时保持该平台能力关闭，不放宽断言。

本机当前 emulator 帮助支持命名 snapshot save/load。`-no-snapshot` 禁自动保存/加载，并覆盖启动时的 `-snapshot`；它不等于禁止控制台手工保存。具体命令序列与退出策略以隔离实测为准。

### B. 休眠状态清单

建议在单设备 AVD 目录内保存版本化 `msd-hibernation.json`，通过现有受控路径派生与原子文件替换写入。只由主进程读写，renderer 不传文件路径、console 端口或快照名。避免无必要地迁移 devices.json 版本。

清单至少描述：schema version、设备 id、快照唯一名/代次、保存时间、保存的 guest boot_id、阶段、emulator 版本、镜像标识与 revision、GPU 后端以及稳定硬件配置指纹。指纹排除端口、运行日志等易变项；在 PoC 中验证 emulator 自写 config 不会误使快照失效。路径和归属由当前设备反查，不信任清单中的任意外部路径。

休眠名使用本应用独占前缀及代次，不能覆盖用户或 Quick Boot 的 default_boot。保存前写入在途记录；保存完成后标记可恢复；所属进程真正退出后提交 hibernated。失败快照不能被普通启动自动选中。

启动扫描将有效且无活体进程的记录投影为 hibernated；保存/退出/恢复中断或发现遗留进程时显示明确错误，不一律重置 stopped。成功恢复后消费该清单；旧快照清理失败可记录重试，但不得导致下次再次加载旧现场。

### C. 状态机与动作矩阵

| 状态 | 主要动作 | 删除入口 |
| --- | --- | --- |
| stopped | 启动、编辑 | 显示；仍受库健康/来源桶限制和确认保护 |
| starting | 取消启动 | 隐藏 |
| running | 停止、休眠、复制 serial | 隐藏 |
| hibernating | 忙态；失败时显示原因和重试/返回运行的可用动作 | 隐藏 |
| hibernated | 恢复、放弃休眠状态 | 隐藏 |
| resuming | 忙态；取消必须保留可重试的快照 | 隐藏 |
| stopping | 原有停止重试 | 隐藏 |
| creating/deleting | 原有事务忙态 | 隐藏 |

主路径：running → hibernating → hibernated → resuming → running。

失败不能统一回退 stopped：保存失败且实例仍活着时尝试恢复运行与媒体；已保存但退出失败时保留资源占用与重试出口；加载失败回到带原因的 hibernated/恢复失败视图。放弃后才进入 stopped。实现时在 shared 和各穷举中定义这些结果，不用 renderer 乐观状态代替。

### D. 主进程事务与互斥

1. 主窗 sender 白名单、id 校验、SDK/迁移/退出门、当前来源桶与运行代次校验全部通过后，同步保留本设备操作资格；重复点击共享在途操作。
2. 锁定新用户输入前释放已按下按键和触点；进入 hibernating 后所有新安装、截图、输入、配置保存和重复生命周期命令均被主进程拒绝。
3. 拒绝该设备活动录屏（包含暂停录制）及 APK 安装；已脱离设备采集的成品封装不应无端阻塞。现有全局安装忙态必要时增加按设备查询，不重构整个任务系统。
4. 排空已接受的截图等在途副作用，有界等待；清理该设备截图编辑会话、投屏、剪贴板与日志连接。失败时不杀实例冒充休眠。
5. 保存命名快照并验证官方返回、文件/清单与后续可恢复条件，提交保存标记；通过已验证的方式退出本设备进程树，确认无监听端口和残留进程后释放登记。
6. 恢复验证兼容性后创建新 runId，分配可用端口并以明确快照启动；去掉与恢复冲突的冷启动参数，保持普通 start/stop 的原有行为。
7. 不能只等 sys.boot_completed=1：同时核对快照加载结果与保存 boot_id，排除 emulator 自动回退冷启动。成功后重新装配媒体/日志，旧 runId/viewToken/截图凭据不能继续使用。
8. 在途 ADB 恢复、SDK 切换、应用退出与休眠互斥；已休眠记录可能随配置/版本变化失效，操作前提示，不悄悄删快照。网络服务、IDE 调试与外部设备资源只承诺重新连接能力。

### E. 用户删除与内部清理分离

- DeviceRow 仅在 stopped 条件下渲染删除按钮，其他状态无 DOM/focus 入口。
- 主窗打开确认前及用户确认后复核最新状态，清理“运行中先停止再删除”的用户文案路径。
- 用户 devicesDelete 通道进入受控删除流程，明确要求 stopped；在最后一次异步加载之后、首个副作用之前同步核验状态，并立刻进入 deleting，避免“IPC 检查过了，但 await 后启动”的窗口。
- 内部 SDK 清理继续使用已授权的系统删除路径，不携带用户的 stopped-only 限制；保留并发合并、元数据写保护、来源桶及路径 containment 守卫。
- 后端拒绝使用已有 locale 域新增明确三语提示，不吞错误。迟到确认框不能停止正在运行的设备。

### F. 体验与权限

沿用现有设备行图标、token、字号与密度；休眠动作有可访问名称和 tooltip，恢复使用明确动作词。右侧已休眠画面提供恢复入口与资源已释放的说明，不把旧画面当实时画面。放弃确认说明“未保存到磁盘快照以外的现场将不再恢复，之后为冷启动”，避免将普通 AVD 数据删除与放弃休眠混为一谈。

错误区分保存失败、进程未退出、快照不兼容和恢复失败，给出可用的重试或放弃动作。对不支持的平台/后端说明原因；不新增系统权限、不外发通知。实现 UI 时读取 impeccable 和现有设计规范；本次计划不修改 PRODUCT.md/DESIGN.md 的历史漂移。
