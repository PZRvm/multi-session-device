# 1.0.1 发布

## Requirements brief

M 级发布任务：用户明确要求将当前 dev 合并 main，发布 1.0.1 并说明更新。范围为 package/lock 版本、发布说明、既定 GitHub PR 与安装包流水线及结果核验；不修改产品行为、不直推 main、不覆盖既有标签或 Release。

## Analysis

本地 dev 包含尚未推送的拖拽排序与投屏修复；main 仍为上次发布合并。当前版本 1.0.0，远端只有 v1.0.0 Preview，无待合并 dev→main PR。release.yml 只接受同仓库 dev→main 已合并 PR，并以精确 merge SHA 构建 macOS ARM64 DMG、Windows x64 EXE 和 SHA256SUMS。

## Design and execution

1. 在 dev 同步 package.json、package-lock.json 至 1.0.1，不创建本地标签；发布模板写明本次功能、修复及休眠能力限制。
2. 运行 typecheck、lint、测试与 book 检查，提交并普通推送 dev。
3. 创建 dev→main PR，确认远端检查通过后用 merge commit 合并。用户本轮已授权发布，无需再次确认。
4. 等待发布工作流，核对标签、Release 版本、merge SHA、双平台附件和 SHA256SUMS；不手动覆盖或提前创建标签。保留原预览版发布方式。
5. 本地 main 快进到远端合并结果，dev 同步该合并；按 book-writeback 记录结果并刷新索引。

## Verification and boundaries

权限沿用已有 gh 登录与流水线配置；PR 和 Release 内容均属于用户授权的发布范围。风险为版本重名、CI 构建失败或附件不全：分别通过预检查、原工作流日志和附件校验确认，不绕过门禁。现场设备卡顿的人工验收仍保持独立记录。

完成条件：main 含 dev 本次代码、版本为1.0.1、Release发布成功并具有两个安装包和校验文件，向用户提供链接及更新摘要。
