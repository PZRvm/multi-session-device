# 1.0.2 发布

## 需求简报

M 级发布任务。用户授权合并 `dev → main`，并修复本次发布遇到的阻塞。当前 `1.0.1` 为 Preview，正式 Sparkle 公钥和私钥已配置。准备下一补丁版本 `1.0.2`，发布首个启用应用内更新的稳定版。

范围是 Windows 安装验证、版本和发布说明、稳定渠道变量、同仓库发布 PR、发布流水线及结果核验。保持当前签名密钥、历史 Preview 和既有发布触发条件。Windows 验收在独立的 CI 测试分支使用测试应用身份、数据目录和环回更新源。

## 分析与设计

- 当前 `dev` 已包含 Mac 更新、Windows NSIS、版本说明窗口及退出保护。`main` 仍指向 `1.0.1` 的发布。原计划的 Windows 真实安装交接需要进一步验证。
- 先用 Windows runner 安装测试版 `90.0.1`，确认更新后由 NSIS 替换为 `90.0.2`，核对重启与数据。在 `dev` 更新版本和说明，跑类型检查、lint、测试和目录索引检查。
- Windows 通过后设置稳定渠道变量，待 PR 检查完成后以 merge commit 合并。发布 Action 从精确合并 SHA 组装双方安装包、更新清单和签名 ZIP，验证草稿资产后公开。
- 以 GitHub 发布结果复核版本、Tag、合并 SHA、附件摘要与 Latest。现有 `1.0.1` 用户先手动安装一次。现场设备场景沿用原计划的验收边界。

## 首发流水线修正

Mac 整仓测试出现日志批次展示失败。检查订阅和 React 渲染的等待条件并复跑整仓测试。GitHub 的 Tag 查询只返回已发布版本，稳定版草稿通过 Releases 列表按精确 Tag 读取。草稿仍须匹配合并 SHA、版本说明和全部附件摘要才能公开。

## 结果

- Windows 隔离 NSIS 升级从 `90.0.1` 到 `90.0.2`，确认后才替换应用，重启后保留数据标记。[Windows 回归](https://github.com/PZRvm/multi-session-device/actions/runs/45158123232)
- 首发 PR 合并提交为 `1fd3c5733c4b1c9e28867cd9e4f7c0504a4920b4`。Mac 重跑通过测试、DMG 校验和正式签名，Windows 正式构建通过。流水线上传全部附件后在查询草稿时报 404。下载同一流水线的产物重验签名与摘要，确认 8 个远程附件、目标提交及版本说明一致后续办原草稿。[合并 PR](https://github.com/PZRvm/multi-session-device/pull/3) · [发布流水线](https://github.com/PZRvm/multi-session-device/actions/runs/45158838866)
- GitHub Latest 指向 `v1.0.2`，Tag 指向首发合并提交。未登录可下载两平台更新清单，内容与核验产物相同。发布后的七项附件摘要与 GitHub 记录一致。[正式版](https://github.com/PZRvm/multi-session-device/releases/tag/v1.0.2)
