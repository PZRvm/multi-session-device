# Stage

项目的开发阶段跟踪。每个文件是一个里程碑，回答"项目接下来走哪、每步做完没"。阶段和步骤由**人**定，agent 只做勾选和建议（权限边界见根目录 `AGENTS.md`）。

## 命名

`01-阶段名.md`、`02-阶段名.md`——序号即执行顺序；创建日期写进 frontmatter。

## 模板

```markdown
---
description: <一行说人话：这个里程碑交付什么>
owner: <阶段负责人；单人项目可省>
created: YYYY-MM-DD
---
# <阶段名>

## 概述

<2~4 行：交付什么、怎么算完成>

## 步骤

- [ ] <功能块，可独立验证>（对应 plan：<链接>）
```

## 规矩

1. 一个 stage 是一个里程碑，可含多个功能。实施细节写在 plans/ 和代码里，这里保持一屏能读完。
2. 勾选三种状态：`[ ]` 未做；`[x]` 完成，**必须附一行结果**（效果如何、遗留什么）；`[-]` 受阻，附一行原因。
3. **勾选条件：该步骤对应的 plan 状态 completed。** stage 不判断实施细节，只确认 plan 已收尾。
4. 步骤可以追加，已有步骤不删——放弃的步骤标 `[-]` 写明原因。
5. 顺序调整由人做；agent 建议的新步骤标 `[suggested]`，人批准才去掉标记。

## 和其他目录的关系

- **上游**：think-report/（调研报告，可选）、需求讨论——人据此立项分阶段。
- **下游**：每个步骤开工时按六阶段流程写 plan/；勾选时回写 learn/（踩坑）和 issue/（遗留）。
- **替代 summary**：原 summary 的"效果"进勾选行的一行结果；"踩坑"进 learn/；"遗留"进 issue/。
