# 调研报告（think-report）

一篇调研回答一个问题：这个功能技术上做不做得成、代价多大——需求、选型、资源量级、合规风险。报告是立项的依据：人读完它决定立不立项、怎么分阶段（见 `stage/README.md` 的"上游"）。

## 什么时候写

需求出现但技术可行性未知时，调研一次。结论落进 stage、plans 和代码之后，报告的职责就完成了。

## 什么时候读

- **读**：人立项分阶段前；后来者做同一主题的调研、需要原始对比材料时。
- **不读**：开发阶段的日常依据。六阶段流程看 `stage/` 和对应 plan，架构事实看 `guidelines/` 和 `docs/architecture/`，决定理由看 `docs/decisions/`。agent 不应为了推进某个开发阶段而重读这里的报告。

## 命名

`YYYYMMDDHHmmss-<标题>.md`，时间戳取调研启动时刻。

实例见 [20260929011713-安卓与iOS多实例模拟器工具](20260929011713-安卓与iOS多实例模拟器工具.md)。
