# BoScope（薄界）

Scope it thin. Gate it hard.

薄界：把界画清——范围、排除、边界先说死，再动代码；阶段一关一关过，不许跳。与 BoWrite 成对：薄写把书写薄，薄界把界画薄——内容薄、边界也薄，薄到一眼见底。

## 目标

把一个功能拆成 **brief → 六个阶段**，每阶段一道硬关卡。动代码前先填结构化需求 brief，并主动提出用户没提到的设计轴。然后一关一关过——不许跳。

**核心原则：** 只说了*做什么*、没说*为什么 / 范围 / 边界*的请求，没到写码的时候。先补缺口；再把用户不知道自己缺的轴摆上来。

## Step 0：需求 brief（必须——在任何代码之前）

渲染下面的 brief 并填满每个槽位。对空槽你有两项义务：

**A. 缺失 → 问。** 真缺口作为问题提给用户。背景和范围不许猜——它们决定造什么。问一次，问全。

**B. 够了 → 推荐。** 信息够开工时别停——把用户没提到的设计轴摆上来（权限、通知、幂等、缓存、事务、边界、回归、生成物同步……）。每条标 `[recommended — confirm or reject]`。补上用户不知道自己缺的缺口。

### Brief 模板

```
## Background
<为什么做这个功能——填或问>

## Scope
- Affects: <会动哪些文件 / 模块 / 数据流>
- Does NOT affect: <明确的排除项——必填；空的排除清单等于范围漂移>
- Boundaries: <输入区间、错误形态、数据形态>

## Requirement
<行为的详细描述——填或问>
```

> **排除项槽位必填。** 空着的"不影响"清单是 Phase 3 越界改动的头号原因。

**设计轴清单（每次都过一遍，相关的提出来）：** 权限 / 鉴权 · 通知 · 幂等 · 缓存失效 · 事务边界 · 并发 / 竞态 · 限流 · 数据迁移 · 回归影响 · 生成物同步（codegen / schema / proto——改动后按项目构建脚本刷新）。

## 六个阶段（每阶段一道硬关卡；上一关没过，下一关不开）

### Phase 1：分析

理解需求 → 找到相关代码 → 追调用链 → 画影响图 → 标风险。**不改代码。**

**产出：** 影响图 + 风险清单。

### Phase 2：设计

**产出：** 数据流、时序图（可选）、文件改动清单、新接口、权限设计、通知设计、测试点。

**停下等批准。** 用户明确批准前不进 Phase 3。（一条明确下令实现并给定技术上下文的开工消息算批准——把依据记进 plan。）

> **权限 + 通知**是 agent 最常忘的两个槽位。哪怕答案是"这次不需要"，也要明说。

**获批后：** 把 plan 写进 `book/plans/YYYY-MM-DD-<feature>.md`（模板在该目录的 README 里）。plan 是施工图——Phase 3 照着这个文件盖，不是照着记忆。

### Phase 3：实现

严格按批准的设计。**不碰范围外的东西，不重构，不加新抽象。** 贴着现有代码的风格写。

### Phase 4：测试（测试先行）

先写一个失败的测试 → 写让它通过的最小实现 → 保持全绿做重构。

**覆盖（全部必查）：** 正常路径 · 权限检查 · 边界（输入区间 / 空值 / 极端值） · 错误路径 · 回归（既有行为不坏）。

**关卡：** 所有相关测试通过，且没有为了通过而削弱断言。

### Phase 5：Code review

对 diff 做结构化 review，检查：重复代码 · 权限漏洞 · 竞态 · 事务问题 · 漏通知 · 漏边界 · 新增复杂度 · 越界改动。

**只记录，不修复。** 顺手修会拆掉关卡——发现进清单，等单独的一轮。项目有 review checklist 就跟着走（`book/guidelines/review-checklist.md`）。

### Phase 6：收尾

回写 book：plan 状态、stage 勾选（附一行结果）、learn 条目、新 issue、changelog——然后重刷索引。**book-writeback** skill 负责模板和质量关卡。

**不变量：** 这里发现的问题**只记录，不修复**。

---

## 约束

- Step 0 先于任何代码，brief 每个槽位填实
- 不许跳阶段；每道必过的关卡过了才进下一关
- Phase 2 设计与 Phase 3 范围边界只在用户明确批准后推进
- Phase 5 只记录不修复；Phase 6 只记录不修复
- 回写目的地是本项目的 `book/`——绝不绕开项目自己的文档约定
