# BoWrite（薄写）

Write it thin. Write it well.

把书读薄是好的读者对厚书做的事。BoWrite 把这件事搬到写作时做：**把书写薄，把笔记写薄，把话说好——内容变少，核心没变。**

两条军令，永远同时生效：

1. **写薄（Thin）**：字更少，信息零丢失。
2. **写好（Well）**：自然、直接、用读者的语言——绝不为了抖机灵牺牲清楚。

## 忠实契约——动刀之前

任何改写不得增加事实、丢掉核心事实、改变责任归属。以下内容永不移动：

- 数字、版本、日期、命令、API 名、参数名、字段名、配置键、日志、报错信息
- 代码块、表格数据、目录结构、链接
- 系统行为主体、领域术语、ADR 结论、责任归属
- 谓词强度："提升了性能"不许弱化成"对性能有点影响"；`性能提升`不许稀释成`涉及性能`
- 含糊的数量保持原样并标注待确认，绝不"取整"成新的说法

丢了事实的削薄不叫削薄——叫损坏。

## 怎么写薄——方法

把书读薄是一门阅读手艺：把书剥到骨架露出，然后合上书复述。写薄就是写作时的同一门手艺。五个动作，按顺序：

### 1. 提骨架 — extract the skeleton

每段用一句话说出它的要点。这些句子就是文档的核心；其余一切都是删减候选。哪段的要点你一句话说不出来，那段还没想清楚自己要说什么——先修它，再削。

### 2. 逐句过刀 — the deletion test

每个句子问一句：删掉它，读者会少知道什么？答案"没什么" → 删。有具体的收获 → 留，再试着说得更短。

### 3. 合并同类 — keep the most specific

同一个意思说了两遍——正文一遍、总结一遍，描述一遍、表格一遍——只留更具体的那份。只复述前文的收尾段，整段删。

### 4. 修饰词折算 — modifiers pay rent

形容词和副词要么折算成具体事实，要么删掉：`非常快` → 多快；`很多问题` → 多少个、哪几个；`进行了优化` → 改了什么、快了多少。

### 5. 复述检验 — the retell test

削完读一遍，合上，复述核心。能复述出来的就是活下来的核心；复述不出来的说明削到核心了——放回去。**内容变少，核心没变——核心保没保住，复述说了算。** 这就是"把书读薄"自己的检验，搬到写作时用。

### 成文示例

厚（62 字）：

> 在进行文档迁移的过程当中，我们总共花费了大约三天左右的时间，对所有的旧文档进行了重新的整理和归类，最终的结果是全部的 120 篇文档都顺利地完成了迁移。

薄（19 字）：

> 迁移花了三天，120 篇旧文档全部归位。

同样的事实活着——三天、全部、120 篇。删掉的是不交租的填充物：`进行`、`大约……左右`、`重新……整理`、`最终的`、`顺利地`。

## 见了就删

- 填充开场白、空洞总结、元评论（`值得注意的是`、`综上所述`、"hope this helps"）
- 一句话说一件事写成了两句，并成一句
- 只解释一次——第一个例子或比喻已经把活干了，重复的删
- 强调词堆叠（`重要 / 关键 / 核心 / significant`）→ 换成背后的具体事实
- 名词化的动词（`进行 / 实现 / 完成` + 动名词）→ 动作本身和它的量
- 长定语链 → 短主语、直接动词
- 二元对比骨架（`不是 X，而是 Y`）通常只留 Y

## 怎么写好——模式账本

真实 review 里抓到的真实模式。这本账是活的：review 里每发现一个新模式就记进来。

### 1. 让读者猜的机灵

比喻写的人读着爽，读的人犯迷糊。一个修辞需要停顿解码一拍，就换成平实的陈述。

- ✗ 更新文档的好处在将来，跳过它的好处在眼前，所以文档**总输**。
- ✓ ……跳过它马上就省事，所以文档**总是作用不大**。
- ✗ 每次都**付全价**。
- ✓ （删——事实句已经说清了，比喻没有增加信息）
- ✗ 不让你顺手修的**这道门，正是……的同一道门**。
- ✓ 只记录、不修复，review 的结论才可信。

### 2. 压缩过头

薄不是电报体。读者第一遍解不开的句子信息量为零——压缩字数，不压缩意思。

- ✗ 到最后没人信文档——**不信也对**。
- ✓ 到最后没人信文档——过时的文档确实不值得信。

### 3. 强调句式

`不是 X，而是 Y` / `正是……的原因` / `同一个……` 都是脚手架；论点通常不需要强调层也站得住。

- ✗ 这条规矩，**正是** review 能保持诚实**的原因**。
- ✓ 只记录、不修复，review 的结论才可信。

### 4. 口语 ↔ 书面的边界

口语节奏落在自然处是受欢迎的（`越做越顺`、`踩坑`、`记一笔`、`顺手多做十二件`）；方言和过于随意的词在文档里要归化：

- `根子` → `根源` · `漂` → `漂移` · `开发点什么` → `开始开发`

### 5. 术语纪律

不借其他领域的术语当日常词用：

- ✗ task notes are `工作记忆`（心理学 working memory 的术语）
- ✓ 任务跟踪

### 6. 翻译腔

多语言文档在目标语言里要**重新表达**，不是逐句翻译。信号：长主语、被动堆叠、`通过……来……`、穿着汉字的英文节奏。

- ✗ `可导航的真相`（"navigable truth" 的硬译）
- ✓ `能查的真相`

### 7. 多语言镜像盲区

在一种语言里治好的病，在它的译文里还活着——同样的比喻和压缩原样幸存，因为没人回头看兄弟版本。修复落在某个语言版本时，同句的其他语言版本必须回查。

- 实例：中文版删掉的 `付全价` / `总输`，英文原版 "at full price" / "always loses" 原样健在——修 A 语言时必须回查同句的 B/C 语言。

### 8. 引言与首节重复

预览全文的开篇段，常常把第一节完整复述一遍——同一屏里同一个论点出现两次。钩子留给引言，事实交给拥有它的那一节。

- 实例：引言说"每开一个新会话都从零开始"，问题 1 又说"每个会话从零开始"——引言留钩子，事实归问题 1。

## 回读——完工前三遍

1. **忠实**：受保护内容完好，事实没丢，术语稳定，删完没有读不通的地方。
2. **薄度**：删掉的是字，还是信息？内容变少，核心没变。核心缩水了就放回去。
3. **残渣**（还觉得有味才做）：开场白、总结收尾、强调句式、机灵、过分均匀的节奏。

终点线是"能发出去了"——不是"听起来像人"。到这就停。
